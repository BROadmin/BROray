Проблемы и восстановление

Найдите точное сообщение или выберите симптом. Для известных ошибок указаны затронутые версии, причина, доступные действия и способ проверки результата.

Известные ошибки обновления

Проверено 1 октября 2026 года. «Подтверждена» означает, что причина отказа установлена. Это не означает, что восстановление уже доступно. Для незакрытых случаев статус указан отдельно.

Обновление не начинаетсяowner-publication-incomplete · восстановление пока не опубликовано. Обновление откатываетсяRUNNING_SNAPSHOT_FAILED · требуется уточнить причину отказа запуска.

Обновление не начинается: owner-publication-incomplete

Подтверждена · готового восстановителя пока нет

Повторное нажатие «Обновить» не исправляет повреждённую блокировку. Обычная перезагрузка сама по себе также не является проверенным способом её восстановления.

Где встречается: пользовательские случаи на 3.1.0-r09c02 и 3.1.1-r12c01. Содержимое повреждённой блокировки получено с роутера на 3.1.0-r09c02. Другие версии нельзя считать проверенными по этим двум случаям.

Сообщение: «Другая операция BROray активна или её блокировка неоднозначна: owner-publication-incomplete. [updater rc=1]».

Причина: каталог общей блокировки сохранился, а сведения о владельце отсутствуют. В подтверждённом случае остались только пустые файлы action и bundle. Старый updater отказывает до скачивания новой версии, поэтому исправление внутри нового архива не может попасть на уже заблокированную установку этим путём.

Что сделать сейчас

  1. Сохраните точное сообщение, номер кандидата и журнал обновления со страницы BROray.
  2. Если доступен SSH Entware, сохраните результат проверки блокировки ниже. Она только читает данные.
  3. Передайте сведения через обращение об ошибке, предварительно удалив секреты. Следите за статусом восстановления на этой странице.

Данные и перезагрузка: приведённая проверка не изменяет серверы, подписки, маршруты, DoT и настройки, не останавливает службы и не требует перезагрузки. Условия будущего восстановителя будут опубликованы после его проверки.

Не удаляйте блокировку вручную. Отсутствие PID не доказывает отсутствие работающей операции. Сообщение о действительно живом владельце требует другого разбора.

Как будет проверяться исправление: запрос обновления принимается, операция завершается успешно, WebUI показывает ожидаемый кандидат, пользовательские данные сохранены. Успех на незаблокированном роутере не закрывает этот случай. Сейчас такого результата для описанной установки нет.

Проверка по SSH: версия и содержимое блокировки

Выполните в оболочке Entware. Команды не удаляют файлы и не запускают обновление. Сообщение «No such file or directory» означает, что соответствующий объект отсутствует; это само по себе не разрешение на ремонт.

/opt/bin/ash <<'BRORAY_READ_ONLY'
export PATH=/opt/bin:/opt/sbin:/bin:/sbin:/usr/bin:/usr/sbin
export LC_ALL=C
date -u
uname -a
cat /opt/broray/current/release.json
for lock in /opt/var/lock/broray/global-operation.lock /tmp/broray-global-operation.lock /opt/var/lib/broray-updater/request.lock; do
    printf '\nLOCK=%s\n' "$lock"
    if [ -L "$lock" ]; then
        ls -ld "$lock"
        continue
    fi
    if [ -d "$lock" ]; then
        ls -la "$lock"
        for name in pid scope action bundle startedAt owner-identity.tsv; do
            file="$lock/$name"
            [ -f "$file" ] && [ ! -L "$file" ] || continue
            wc -c "$file"
            sha256sum "$file"
        done
    else
        ls -ld "$lock" 2>&1
    fi
done
BRORAY_READ_ONLY

Откат обновления: RUNNING_SNAPSHOT_FAILED

Подтверждён один из источников ошибки · проверка исправления продолжается

Общее сообщение SERVICE_START_FAILED обозначает отказ запуска службы. Причину нужно искать в строках перед ним.

Где встречается: при обновлении с 3.1.0 и 3.1.1 до ранних сборок 3.2.0, включая 3.2.0-r02c01 и 3.2.0-r03c01. В журналах после RUNNING_SNAPSHOT_FAILED выполняется откат.

Подтверждённая причина: прежний код чтения конфигурации зависел от утилиты timeout, которой на части установок Entware нет. BusyBox может быть установлен без этого модуля. Увеличение времени ожидания не добавляет отсутствующую утилиту. Само сообщение RUNNING_SNAPSHOT_FAILED не доказывает именно эту причину: чтение конфигурации может завершиться другой ошибкой.

Что сделать сейчас

  1. Сохраните журнал целиком, включая строки перед SERVICE_START_FAILED и итог отката.
  2. После ROLLBACK=PASS проверьте, что открывается прежний WebUI, работает VPN и доступны ваши серверы, подписки, маршруты и DoT. Если откат не завершился, передайте журнал в поддержку до новых изменений.
  3. При наличии SSH проверьте доступность утилиты командой ниже. Если она отсутствует, приложите результат к обращению.
Проверка по SSH: есть ли timeout

Проверка выводит доступные возможности и ничего не устанавливает.

/opt/bin/ash <<'BRORAY_TIMEOUT_CHECK'
export PATH=/opt/bin:/opt/sbin:/bin:/sbin:/usr/bin:/usr/sbin
if command -v timeout; then
    printf 'standalone timeout: found\n'
else
    printf 'standalone timeout: not found\n'
fi
if [ -x /opt/bin/busybox ]; then
    if /opt/bin/busybox --list | grep -x timeout; then
        printf 'BusyBox timeout: found\n'
    else
        printf 'BusyBox timeout: not found\n'
    fi
else
    printf '/opt/bin/busybox: not found\n'
fi
BRORAY_TIMEOUT_CHECK

Статус решения: в тестовых кандидатах зависимость заменена поставляемым исполнителем; проверка на стенде без внешнего timeout прошла. Повторное обновление на исходном проблемном роутере ещё не подтверждено. Это не рекомендация самостоятельно устанавливать тестовый кандидат.

Данные и перезагрузка: диагностика не меняет настройки и не требует перезагрузки. При самом обновлении и откате службы перезапускаются, поэтому возможен перерыв VPN.

Как проверить исправление: на установке без внешнего timeout обновление заканчивается успешно без отката, WebUI и VPN работают, пользовательские данные сохранены. Одного изменения номера версии или увеличения ожидания недостаточно.

WebUI не открывается

  1. Проверьте локальный адрес BROray и попробуйте LAN-доступ до проверки KeenDNS.
  2. Если WebUI всё ещё недоступен, переходите к расширенной проверке служб ниже.
  3. Не переустанавливайте BROray многократно до выяснения причины.

Не удаётся войти

Для WebUI используется учётная запись Keenetic. Не публикуйте пароль или данные сессии в обращении поддержки.

Сервер не проходит проверку

Откройте «Серверы», повторно проверьте конфигурацию и сохраните точный текст результата. Не меняйте Xray или Keenetic вручную до определения причины.

Сервер активен, но трафика нет

  1. На Главной проверьте активный сервер и состояние Xray.
  2. На странице Keenetic проверьте, что управляемый ProxyN подключён и соответствует активному серверу.
  3. Если состояние неоднозначно, скачайте диагностический отчёт.

Подписка не обновляется

Запустите обновление на странице «Подписки» и сохраните точный текст ошибки. Ссылка подписки является секретом: не публикуйте её в Issues, Telegram или скриншотах.

Маршрут не работает

  1. Откройте нужный набор и выполните проверку локального состояния и фактического Keenetic.
  2. Если интерфейс предлагает восстановление или продолжение операции, используйте штатное действие.
  3. Не удаляйте чужие или общие маршруты вручную.

Проблема с DNS-over-TLS

Сначала выполните свежую TLS/SNI-проверку выбранных серверов, затем повторите применение. BROray удаляет только подтверждённые управляемые записи и сохраняет внешние DoT/DoH.

Ошибка обновления

  1. Откройте страницу BROray и сохраните журнал текущей операции.
  2. Сопоставьте точное сообщение с известными ошибками выше.
  3. Если выполняется другая операция, дождитесь её результата. Не удаляйте lock-файлы вручную.
  4. Используйте штатное восстановление только для поддерживаемого им случая. Для owner-publication-incomplete в старых версиях готового восстановления пока нет.
Расширенная диагностика и данные для поддержки

Проверка и диагностика

На странице BROray доступны фоновые операции, журнал и скачивание диагностического отчёта. Можно остановить отменяемые задачи и поставить автоматические запуски на паузу. Защищённые этапы маршрутов не прерываются.

Восстановление освобождает блокировку только после проверки владельца и дочерних процессов. Если операция активна или её состояние неоднозначно, блокировка сохраняется. Восстановление самих маршрутов выполняется на страницах маршрутов.

/opt/broray/bin/broray-system info
/opt/bin/broray-updaterctl version
/opt/bin/broray-updaterctl check
/opt/bin/broray-updaterctl status
/opt/etc/init.d/S22broray-updater status
/opt/etc/init.d/S23broray-monitor status
/opt/etc/init.d/S24broray status
/opt/etc/init.d/S25broray-web status

Для текущего Stable ожидаются release 3.2.0-r12, кандидат 3.2.0-r12c01, WebUI WebUI-3.2.0-r12c01, пакет 3.0.0-r14, broray-updater/5, канал Stable и отсутствие доступного обновления.

Если что-то не получилось

WebUI не открывается

  • проверьте адрес http://<локальный-IP-роутера>:8080/; адрес 192.168.1.1 подходит только при такой настройке вашей сети;
  • убедитесь, что устройство подключено к домашнему Keenetic;
  • временно отключите мобильный интернет на телефоне;
  • очистите кэш сайта или откройте страницу в другом браузере.
