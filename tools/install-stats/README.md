# Статистика BROray

Приёмник принимает `POST /v1/install-events` от всех версий BROray, которые отправляют события по этому контракту. Ответ HTTP 200 с исходным `eventId` означает, что транзакция SQLite завершена или это повтор того же события. Инвентарь сборок в формате массива `[версия, ревизия, архитектура]` используется при импорте счётчиков скачиваний.

```sh
python3 receiver.py --database metrics.sqlite3 serve
python3 receiver.py --database metrics.sqlite3 report
python3 receiver.py --database metrics.sqlite3 import-downloads --allowlist releases.json --input snapshots.json
```

Служба открывает только локальный порт. Для HTTPS подготовлен отдельный виртуальный хост `stat.brovibe.cloud` с маршрутом `/v1/install-events`. При размещении рядом с текущим сервером загрузок используйте `CNAME stat → api.brovibe.cloud` и сертификат на `stat.brovibe.cloud`. Конфигурация передаёт приёмнику только заголовки, нужные для обработки тела. В виртуальном хосте журналы запросов отключены. Файл SQLite хранится в закрытом каталоге. Отчёт доступен через локальную команду и содержит агрегаты за дни по Москве. Ключи устройств и идентификаторы событий не выводятся. [Конфигурация приёмника](deploy/stat.brovibe.cloud.nginx.conf)

Для тестового приёмника используйте отдельный файл SQLite. После запуска проверьте сертификат `stat.brovibe.cloud`, точный ответ для тестового события и отсутствие тел и адресов в журналах промежуточных сервисов. Адрес приёмника задаётся при сборке через параметр компоновщика:

```text
-X github.com/BROadmin/broray/internal/installstats.Endpoint=https://stat.brovibe.cloud/v1/install-events
```

Для скачиваний импортируется массив снимков. Каждый снимок содержит `channel` (`GitHub` или `Stable`), `asset` (идентификатор экземпляра архива в этом источнике), `day` (день Москвы в формате YYYY-MM-DD), `version`, `revision`, `architecture` и накопительный `total`. Если источник недоступен, `total` равен `null`. Для переизданного экземпляра используйте новый идентификатор. Отчёт вычисляет суточный прирост между соседними измеренными днями и отдельно отображает первое наблюдение, пропуск, сброс или недоступность.

Сборщик читает метаданные [GitHub Release Assets](https://docs.github.com/en/rest/releases/assets?apiVersion=2026-03-10) и локальный агрегированный экспорт Stable. В JSON-инвентаре архивов указываются `version`, `revision`, `architecture`, `name`, `size`, `sha256`, `githubId` и `stableAsset`. Идентификатор недоступного для архива источника задаётся как `null`. Экспорт Stable имеет поля `schema` со значением 1, `day` и `archives` со списком записей `asset`, `sha256`, `size`, `total`. Сборщик сверяет идентичность экземпляра с инвентарём. Если экспорт отсутствует или относится к другому дню, Stable остаётся недоступным для этого прогона.

```sh
python3 collect.py --database metrics.sqlite3 --archives archives.json --stable-export stable-totals.json
```

На origin Stable экспорт можно построить из отдельного журнала для архивов. Формат строки `секунды.миллисекунды|идентификатор-архива|байты-тела`. В журнал попадают только ответы `200` на `GET` для точных путей архивов из проверенного инвентаря. В этих обработчиках используется отдельный формат журнала с тремя полями. Для учёта не требуется IP, путь запроса, заголовки или тело. Загрузки частями, перенаправления и оборванные ответы не образуют отдельных скачиваний. [Условный журнал nginx](https://nginx.org/en/docs/http/ngx_http_log_module.html)

В существующих обработчиках точных путей установите `$broray_archive_id` из инвентаря и включите конфигурацию подсчёта. Маршруты архивов обслуживает `api.brovibe.cloud`. [Формат журнала](deploy/stable-count-http.nginx.conf) [Конфигурация обработчика архива](deploy/stable-count-location.nginx.conf)

Перед запуском экспорта закройте или ротируйте журнал. Передайте весь набор файлов за период учёта каждого архива, каждый файл один раз. При отсутствии полного набора данных пропустите экспорт. Импорт отметит источник недоступным. Для расчёта счётчика на конец московского дня укажите этот день в параметре `--day`.

```sh
python3 stable_export.py --archives archives.json --ledger rotated-archives.count --day 2026-11-24 --output stable-totals.json
```

Чтобы импортировать закрытый московский день после полуночи, передайте `--stable-day 2026-11-24` сборщику вместе с экспортом. Снимок GitHub продолжит относиться к дню его фактического получения.
