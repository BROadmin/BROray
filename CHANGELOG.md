# История изменений

## 3.0.0 / OPKG 3.0.0-r14 — Stable — 2026-08-25

- опубликован Stable из byte-exact технического кандидата `3.0.0-r14c68`;
- исправлено отображение канала обновлений после Stable-установки: WebUI читает фактический active index updater-v5 и показывает `Стабильный`, даже если legacy OPKG feed остался staging;
- внедрён постоянный `broray-updater/5` с компактными app-slot, атомарным переключением, проверкой здоровья и автоматическим откатом;
- один проверяемый установщик обслуживает чистую установку, обновление исправной ветки 3.x и переустановку текущего кандидата;
- Xray runtime и пользовательское состояние отделены от сменяемого приложения;
- полностью переработан авторизованный WebUI; физический аудит прошли 12 из 12 страниц, 162 из 162 кнопок и 165 из 165 элементов управления;
- Главная переведена на атомарные фоновые снимки, тяжёлые read-only endpoints получили ограниченный кэш, скрытые страницы прекращают дорогой polling;
- исправлен разбор VLESS Reality/Vision, TCP/raw, XHTTP, VMess, Trojan и Hysteria2;
- управляемый интерфейс Keenetic получил динамическое имя `BROray - <активный сервер>`, проверку владения, создание, восстановление и синхронизацию;
- DNS-over-TLS отделён от маршрутов, поддерживает до восьми проверенных записей и сохраняет внешние DoT/DoH;
- маршруты получили пакетный импорт больших наборов, предварительный rollback-intent и точный откат по одному свежему снимку Keenetic;
- обязательная физическая ошибка после 20 из 40 маршрутных изменений завершилась 20 обратными действиями, без утечек и с восстановлением исходного состояния;
- исключены только volatile-заголовки экспорта Keenetic `Last change` и `Username`; семантические изменения маршрутов и других настроек по-прежнему отклоняются;
- Xray обновляется и переустанавливается с динамическим расчётом места вместо ошибочного фиксированного требования 102 МиБ;
- физические update и same-candidate reinstall `r14c68` завершены без перезагрузки; после Stable-публикации updater подтвердил текущий кандидат и отсутствие обновления, конфликтующих lock нет;
- прямое обновление с 2.x не поддерживается: требуется сохранение данных и чистая установка.

## 2.2.7 — в разработке, не релиз — 2026-08-04

- утверждён обязательный контракт обновления `RELEASE-REQUIREMENTS.md` версии 1.7;
- сохранена исходная схема с одной полной проверенной резервной копией только в `/tmp/broray-update-<operation-id>/backup.tar.gz`;
- начальная allowlist-очистка закреплена как первое изменение управляемого хранилища после read-only проверок и атомарной блокировки;
- добавлены operation-id, атомарная блокировка через `mkdir`, отдельные журналы этапов, exact previous IPK, backup-contract, protected-data manifest и persistent-маркер прерванной операции;
- update и reinstall обязаны использовать один transaction runner из `/tmp`;
- backup, candidate, previous/rollback IPK и staging запрещено размещать на `/opt`;
- добавлена обязательная трассировка `требование → код → тест → доказательство` и static gate запрещённых путей;
- закреплены BusyBox/Entware-совместимость, `/opt/tmp -> /tmp`, отказ от обязательных `flock`/`paste`, устойчивое определение процессов и проверка WebUI по фактическому LAN-listener;
- экспериментальная ветка с `/opt/var/tmp/broray-transactions` и раздельной копией пользовательских данных отозвана до установки на физический роутер;
- `BROray-2.2.7-exact-preflight-r4.run.sh` и кандидат с SHA-256 `ea85866086e754c5e03abbee6e33f4b0f307c26101351467dc22052f0fa34e3d` не являются релизными артефактами;
- реализация 2.2.7 должна быть пересобрана и заново пройти полный gate версии 1.7.

## 2.2.5 / OPKG 2.2.5 — 2026-07-31

- публичный OPKG-feed и документация опубликованы атомарно; обычная и no-cache загрузки IPK совпали с `Packages`;
- переход `2.1.1-2 → 2.2.5` успешно завершён через WebUI на реальном Keenetic;
- исправлено чтение `SHA256sum` из сжатого локального `src/gz` и передача `BRORAY_OPKG_LISTS_DIR` фоновому worker старого WebUI;
- перед установкой удаляются старые автоматические копии и управляемый мусор, затем создаётся одна актуальная проверенная копия только в `/tmp`;
- BROray позиционируется как полноценный клиент Xray для современных Keenetic и Netcraze, а не только менеджер конфигураций;
- финализирован адаптивный WebUI для компьютера, планшета и телефона;
- добавлена отдельная страница DNS-over-TLS, предустановки Яндекс DNS и поддержка вложенного running-config Keenetic;
- исправлены фактическая сверка DoT/DoH, лимит восьми серверов, сообщения этапа ошибки и транзакционный откат;
- добавлена отдельная кнопка обновления Xray; обновление и переустановка разделены;
- исправлен JSON backend проверки обновления и безопасной очистки BROray;
- маршруты разделены на обзор, свои маршруты и готовые маршруты;
- добавлены подпункты раздела маршрутов в меню;
- девять готовых наборов работают через один агрегированный summary;
- пользовательские BAT анализируются как текст и никогда не выполняются;
- единое окно прогресса открывается сразу, поддерживает остановку после текущего маршрута и продолжение;
- в покое polling маршрутов сокращён, скрытые вкладки не опрашивают backend, параллельные запросы не накапливаются;
- сохранён единый реестр владельцев общих маршрутов;
- добавлены восстановительная переустановка, безопасная очистка, технические журналы и полный жизненный цикл BROray;
- релиз собран из проверенной контрольной точки реального роутера.
