# S23: идентификация и остановка монитора

Исходный S23 проверяет PID и два аргумента командной строки, затем отправляет TERM/KILL по числу PID. Между проверкой и сигналом процесс может измениться. Если принадлежность вообще не подтверждена, `stop` удаляет PID-файл и сообщает, что монитор не запущен. `restart` продолжает запуск после `stop` без проверки результата.

Физическое воспроизведение до production edits: `docs/evidence/monitor-identity-reproducer-20260915` в корне проекта. В отдельном каталоге создан неизвестный PID-файл, `/proc` заменён пустым fixture-каталогом; daemon не запускался. Реальный исходный S23 удалил неизвестный файл. Ожидаемый FAIL подтверждён, тестовые объекты удалены по точному списку.

План исправления: добавить connection-monitor в фиксированный список общего service lifecycle, заменить S23 тонким адаптером, регистрировать полную identity и generation в самом daemon до его файловых изменений. Остановка через generation-bound request; проверка между циклами и во время ожидания. Неизвестные старые PID-файлы сохраняются с явной ошибкой. Restart допустим только после успешной остановки и освобождения lifetime lease.

Монитор выполняет `current-address`, ping и обслуживание журнала последовательно. Cooperative stop не прерывает незавершённый дочерний вызов: при задержке контроллер обязан вернуть pending, а не сообщать об остановке. Остановка не должна затрагивать постоянный Xray. Нужны реальные проверки пустого/неизвестного состояния, start/stop, конкурентного запуска, устаревшего stop, задержанного цикла и самопадения daemon.

Публикация диагностического connection-status и обслуживание текстового журнала остаются отдельным storage gate. Перевод S23 не доказывает сохранность этих файлов при отключении питания.
