# BROray 3.5.3 — матрица параметров Xray 26.11.9
> Поправка 3.5.6: прежние отметки об отклонении Hysteria masquerade ниже описывают исторический аудит. Теперь известный серверный блок проверяется и пропускается с предупреждением, не применяется на клиенте. Остальные строки аудита не пересматривались. [Приёмка](ACCEPTANCE-3.5.6.md).


Матрица описывает выбранный контракт импорта; полный статический перечень, включая неподдержанные клиентские поля, находится в [реестре схем](XRAY-26.11.9-SCHEMA.md). Наличие имени теста в старой строке не доказывает отдельную проверку каждого её поля. Расширенные проверки перечислены в документе приёмки.  `supported` означает поддержку модели в указанных пределах, а не аппаратную совместимость или проверку настоящего облачного аккаунта. Итоговая приёмка находится в [ACCEPTANCE-3.5.3.md](ACCEPTANCE-3.5.3.md). Требование нового ядра применяется перед подключением/проверкой и понижением Xray; сохранение профиля на старом ядре разрешено с предупреждением.

Основа BROray: b66eb60bcaa56fe5041a19df8efe60e6d07b18c0. Схемы закреплены тегом [Xray v26.11.9](https://github.com/XTLS/Xray-core/tree/v26.11.9/infra/conf). Сверены [MASQUE](https://github.com/XTLS/Xray-core/blob/v26.11.9/infra/conf/masque.go), [транспорты](https://github.com/XTLS/Xray-core/blob/v26.11.9/infra/conf/transport_method.go), [VLESS](https://github.com/XTLS/Xray-core/blob/v26.11.9/infra/conf/vless.go), [XDRIVE template](https://github.com/XTLS/Xray-core/blob/v26.11.9/transport/internet/xdrive/template.go). Runtime-поведение не выводится только из структуры Go.

Общий контракт: свежий JSON ≤2 MiB, глубина ≤64, один UTF-8 документ без повторных ключей и хвоста. Неизвестные исполняемые поля дают ошибку без значения. Старые записи читаются совместимо, без повторного строгого импорта. Приватные TLS/transport/auth данные сохраняются в записи, защищённой копии и outbound; публичный API их маскирует. Все числовые диапазоны указаны включительно. `Прежняя политика` не добавляет искусственного нового minimumCore.

Для URI отсутствие optional-поля использует ранее принятую нормализацию. Для прямого native JSON false/0/строки диапазонов сохраняются; null не заменяет обязательное значение. `rejected-with-reason` означает явный отказ до изменения каталога; `metadata-warning` — неисполняемую информацию/формат с объяснением.

## Доказательства и пределы

Дополнительная проверка 3.5.3 охватывает типы, границы, контейнеры и сочетания из [реестра схем](XRAY-26.11.9-SCHEMA.md). Вложенные FinalMask проходят строгую проверку схемы при новом импорте; семантика криптографических значений, PEM и XDNS остаётся за обязательной проверкой конфигурации ядром перед запуском. Старые сохранённые записи не переимпортируются.

- Независимые RED/GREEN: context/Trojan/legacy aliases/Hysteria idle; дубли JSON; private nested headers; native import/backup; runtime gate; signed keepalive обоих путей; template context и cloud monitor. Полные servers/subscriptions проходили промежуточные проверки; финальный прогон после общей правки обязателен.
- Xray 26.11.9 ARM64 в offline VM: native config для Google Drive, S3, template, local, MASQUE и WARP; реальные TCP/UDP для local/S3/template и MASQUE H2/H3. S3 SigV4 проверен приватной оснасткой. Template OAuth refresh/401 и 429, S3 429 пройдены с настоящими Xray и тестовым API.
- MASQUE H2/H3: домен разрешён через отдельный DNS на стороне сервера, IPv6 TCP/UDP переданы; недоступный H3 не пропускает обходной UDP. Это не WARP account PASS. Первые ошибки оснастки сохранены в WORKLOG.
- Реальный Google Drive/WARP и внешний путь облачного API вне ProxyN не проверены. Сборки четырёх архитектур, offline обновления с 3.5.0–3.5.2 и выбранные аппаратные сценарии кандидатов 1–3 приняты; отдельные ограничения MIPS/WireGuard сохранены. Актуальная граница: [приёмка](ACCEPTANCE-3.5.3.md).
- Пять первоначальных групп находок привязаны к TestTrojanRejectsVlessOnlyFields, TestURIFieldContext, TestLegacyVMessAliasConflict, TestHysteriaIdleTimeoutBounds, TestImportValueSemantics; дополнительные случаи и журнал не заменяются обновлением этой таблицы.

Матрица не обещает поддержку произвольной полной конфигурации Xray. Любая строка вне объявленного клиентского контракта требует отдельной оценки и проверки, а не молчаливого удаления поля.
