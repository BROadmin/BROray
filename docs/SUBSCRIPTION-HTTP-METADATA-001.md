# Получение подписок, HWID и метаданные — этап 7

База: b8aab47470d8a0cdee39be374c349723aac176e0. Это готовые изменения для интеграции, не релиз.

## Контракт

По умолчанию User-Agent берётся из версии приложения в share/release/manifest.json;
config/version — резервный источник. Если версия неизвестна, используется BROray/unknown,
а не выдуманная или жёстко заданная старая версия. Необязательный httpUserAgent задаётся
самим пользователем в существующей форме подписки. Максимум 128 печатных ASCII-символов.
Пустая строка возвращает автоматический режим. Чужой клиент автоматически не имитируется.

Существующее создание/хранение clientHwid не изменено. Один и тот же идентификатор передаётся
при повторных запросах и перенаправлениях; после отказа провайдера не генерируется новый.
Остальные сведения об устройстве и произвольные HTTP-заголовки не добавлены.

Разбирается последний блок HTTP-заголовков; информационные ответы и trailers исключены.
Location и Content-Type читаются без зависимости от расширения IGNORECASE конкретного awk.
Противоречащие Location и HWID-флаги отклоняются. HWID-отказ распознаётся по явным флагам
x-hwid-max-devices-reached, x-hwid-limit, x-hwid-not-supported при 2xx, 4xx и 5xx.
Один HTTP 404 сам по себе не считается доказательством ограничения устройств.

Каждое перенаправление проходит прежнюю проверку URL/адреса и curl --resolve.
Автоматический --location не включается. HTTPS → HTTP запрещён. Поддержан относительный
Location с новой query string. --disable игнорирует curlrc, --globoff выключает URL globbing.
Существующие таймауты, лимит тела и максимум три перенаправления сохраняются.
Сжатие запрашивается только при curl >= 8.20, когда --max-filesize ограничивает также
распакованный результат. Для более старого curl запрашивается identity; неожиданный
сжатый ответ отклоняется. Наличие пункта --max-filesize проверяется как прежде.
Для старых curl это не новая гарантия жёсткого ограничения растущего файла во время передачи:
сохраняются проверка размера после загрузки и таймаут. Заголовки проверяются до разбора (64 КиБ).

## Метаданные и приоритеты

Поддержаны profile-title, subscription-userinfo (upload/download/total/expire),
profile-update-interval, announce, announce-url, support-url, profile-web-page-url.
HTTP, строки #key: value и известные незакомментированные body headers распознаются
до очистки. Обрабатываются метаданные вокруг Base64 и внутри однократно декодированного тела.
Валидное значение тела приоритетнее HTTP. Более внутренний слой приоритетнее внешнего.
Конфликтующие значения одного поля в одном слое не выбираются произвольно; поле пропускается.
subscription-userinfo считается одним составным полем: значение тела заменяет HTTP-поле целиком.

Название и интервал, заданные пользователем, НЕ перезаписываются. Имя провайдера и его
рекомендованный интервал показываются отдельно. Интервал провайдера переводится из часов
в минуты, допустимы 1–168 часов. Нулевые total/expire не превращаются в обещание безлимита.
Неполные счётчики не дополняются выдуманными нулями. Сообщения/ссылки выводятся как данные,
HTML экранируется; ссылки доступны только по клику, http/https, без credentials и с noopener.
Routing, update-always и custom-tunnel-config не применяются; сохраняются только имена
распознанных, но проигнорированных директив, без их содержимого.

providerMetadata — необязательный объект schemaVersion 1 в существующей записи подписки.
Метаданные готовятся в приватной папке операции. В постоянную запись попадают только после
завершения supervised helper и успешной синхронизации серверов. Сбой загрузки, разбора
или синхронизации сохраняет прежние сведения; WebUI отмечает их неподтверждённость.
Успешный новый ответ без метаданных очищает старые поля. Изменение URL очищает сведения
предыдущего провайдера. Формат серверов, алгоритм ID, updater и политики Keenetic не меняются.
