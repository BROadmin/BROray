# Дневник проекта BROray

## 2026-08-04 — утверждён контракт обновления 1.7

### Исходная точка

- Для BROray 2.2.7 выполнялась системная стабилизация по полному снимку Keenetic Peak KN-2710 с установленной BROray 2.2.6.
- В ходе работы был создан экспериментальный транзакционный механизм с размещением рабочих файлов в `/opt/var/tmp/broray-transactions` и отдельной копией пользовательских данных.
- Экспериментальная схема прошла внутренние тесты, но не соответствовала ранее утверждённому обязательному порядку обновления.
- Физический `exact-preflight r4` не устанавливал пакет, но показал последствия неверной архитектуры: расчёт места выполнялся для rollback и копий на `/opt`, появились ложные/вторичные блокировки.

### Решение пользователя

Исходная схема не заменяется. Она усиливается полезными механизмами контроля без переноса резервной копии и staging на `/opt`.

Канонический порядок:

```text
read-only проверки
→ operation-id и атомарная блокировка
→ allowlist-очистка мусора
→ повторный контроль /opt и /tmp
→ фиксация служб и манифеста защищаемых данных
→ остановка ранее работающих служб
→ одна полная backup.tar.gz в /tmp
→ проверка backup-контракта
→ точный previous.ipk в /tmp
→ точный candidate.ipk в /tmp
→ установка
→ комплексный postcheck
→ восстановление исходного набора служб
→ ограниченный постоянный журнал
→ удаление временной транзакции
```

### Что сохранено из экспериментальной схемы

- уникальный `operation-id`;
- атомарная блокировка через `mkdir` без `flock`;
- отдельные журналы этапов;
- SHA-256 и версионируемый backup-контракт;
- фиксация исходного состояния пяти служб;
- манифест защищаемых данных как доказательство, а не отдельная копия;
- точная проверка previous/candidate IPK;
- единый runner обновления и переустановки;
- persistent-маркер прерванной операции;
- bounded postcheck с повторными попытками;
- автоматическая трассировка `требование → код → тест → доказательство`.

### Что запрещено и отброшено

- backup, candidate, previous/rollback IPK или staging в `/opt`;
- `/opt/var/tmp/broray-transactions` как рабочее хранилище;
- `/opt/broray/backup/user-data-before-*` как замена полной копии;
- разделение обязательного backup на независимые частичные архивы;
- отдельные движки для update и reinstall;
- обязательные необъявленные зависимости `flock`, `paste`;
- проверка WebUI только через `127.0.0.1`;
- определение Xray только по полному пути процесса;
- выдача кандидата до сверки с каноническим контрактом.

### Отозванные артефакты

Следующая архитектурная линия не является основанием для релиза:

```text
BROray-2.2.7-exact-preflight-r4.run.sh
broray_2.2.7_aarch64-3.10.ipk
SHA-256 IPK: ea85866086e754c5e03abbee6e33f4b0f307c26101351467dc22052f0fa34e3d
```

Preflight не запускал установку, поэтому рабочая BROray 2.2.6 на Keenetic Peak KN-2710 не заменялась.

- Требования обновлены и становятся блокирующим источником истины.
- Реализация BROray 2.2.7 должна быть перестроена по контракту 1.7.
- До нового immutable candidate и полного requirement gate действий пользователя на роутере не требуется.
- Следующая точка участия пользователя — read-only preflight нового кандидата, уже привязанного к требованиям 1.7 и его точному SHA-256.
