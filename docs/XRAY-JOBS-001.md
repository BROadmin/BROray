# XRAY-JOBS-001 — владелец установки и подтверждение отката

Установщик Xray сохраняет неоднозначную старую resource lock. CLI получает собственное задание; CGI передаёт право выполнения отдельному worker через проверяемую identity и смену token. Worker остаётся владельцем после ответа HTTP 202. Скачивание, распаковка и предварительная проверка выполняются в частном каталоге под native supervisor с пределом 600 секунд.

До остановки Xray подтверждается завершение временных helpers, после чего операция переходит в защищённую фазу. Ошибка отката не маскируется: результат сообщает `rollbackSuccess:false`, резервный бинарник и global fence сохраняются. Успешный откат проверяет SHA256 предыдущего бинарника и, если VPN был запущен, состояние runtime/SOCKS. Удаление временных файлов ограничено текущим заданием. Статус WebUI использует состояние общего coordinator, GET не удаляет старые PID-файлы.

## Проверки

- Linux: 8 installer/CLI/WebUI backend scenarios плюс 3 фактических handoff integration checks.
- Физический ARM64: 7 сценариев production installer/coordinator. Используются специально скомпилированные native binary fixtures и локальный transport. Проверены установка, отмена, оба результата отката, handoff после выхода CGI и сохранение неизвестной блокировки.
- Исходный FAIL удаления неизвестной блокировки сохранён отдельно в `xray-lock-reproducer-20260915`.
- Архив физического прогона: `52d9f5f4e26dd83dd7240915cb17c9d09ab30959d3507fdbc5b228ebaada1d07`. Тестовые каталоги удалены после архивирования.

## Остаётся до релиза

Физические проверки этого checkpoint не запускали постоянный Xray и не доказывают работу реального VPN. Требуются durable transaction/recovery после SIGKILL/reboot в защищённой фазе, ограничение накопления результатов старых WebUI jobs, остальные mutating producers и service lifecycle, полная установка/обновление/откат и длительная приёмка. Release-ready и publication не заявляются.
