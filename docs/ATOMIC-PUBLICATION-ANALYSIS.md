# Короткая публикация состояния: анализ и контракт

Исходный код: SERVICE-LIFECYCLE-001, `259114519769419f13cc75e640720972da918313`. В изолированном Linux воспроизведена смерть настоящего auto-switch job сразу после успешного native replace, до выхода из committing. Файл состояния содержит operationId, владелец мёртв, но recover возвращает `protected_recovery`. Ожидаемый FAIL: `docs/evidence/atomic-publication-reproducer-20260915` в корне проекта, 1 проверка, 14,259 с. Production edits до воспроизведения не выполнялись.

## Выбранный механизм

Сам coordinator под общим flock выполняет короткую публикацию одного JSON. Первые ресурсы: состояние автовыбора и результат измерения сервера. Адрес назначения определяется фиксированным resource enum и проверенным server ID. Данные ограничены по размеру и схеме. Внешний source только читается; coordinator формирует собственный private временный файл рядом с назначением.

Запрос связывается с полной identity executor, token, случайным nonce и ожидаемой revision. При потере ответа повторяется тот же запрос. Старый запрос после следующей revision не имеет права записывать прежние данные.

До входа в committing сохраняется свидетельство: operationId, resource/key, nonce, исходная revision/phase/cancelability, SHA-256 прежнего и нового содержимого. После durable замены восстанавливается прежняя фаза, затем свидетельство помечается завершённым. Это один ограниченный файл на operation. Необработанное свидетельство запрещает обычный tick/finish.

После подтверждённой смерти owner и отсутствия helper recovery под тем же flock допускает только исходное либо новое содержимое из свидетельства. Native sync подтверждает файл и родительский каталог; ошибка fsync сохраняет блокировку. Любое третье содержимое, symlink/hardlink, несовпадение revision или неизвестный временный файл сохраняется и блокирует восстановление.

Публикация внутри protected транзакции возвращается в её прежний protected режим. Она не даёт права завершить внешнее переключение Xray, активацию сервера или многофайловое обновление подписки.

## Требуемые проверки

Повтор ответа; устаревший запрос после следующей публикации; отмена до границы; чужая identity; недопустимые resource/key; небезопасные source/target; self-crash до и после каждого durable перехода; третье содержимое; отказ fsync; сохранение внешней protected транзакции; настоящий auto-switch producer. Различать fake identity matrix, реальные Linux процессы и физический ARM64. Все физические assertion regressions завершаются до изменения native ABI.

## Проверка retirement

После focused Linux 39 PASS и физического прогона 10 PASS добавлен отдельный native sync после удаления уже подтверждённого pending-файла. Он сохраняет удаление записи каталога перед завершением свидетельства. Повторная физическая матрица на окончательном коде: 10 PASS. Первый широкий Linux-прогон остановился из-за накопления временных копий приложения в тестовом окружении. Результат сохранён отдельно; после добавления очистки test fixtures широкий прогон повторяется уже с окончательным sync. Производственный код для исправления нехватки места в harness не менялся.

Общие временные файлы `ops_write` с суффиксом PID и прерывание записи самих служебных JSON входят в следующий storage/crash gate. Их нельзя считать проверенными отключением питания по self-SIGKILL между законченными durable переходами.
