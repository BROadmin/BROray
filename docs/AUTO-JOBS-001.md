# AUTO-JOBS-001 — отдельный владелец автоматического цикла

Исходный цикл обходил общую паузу и записывал состояние. Исправленный daemon запускает отдельный job, который получает admission и выполняет проверки через service API без повторного захвата собственного global fence. Автоматическая проверка недоступного сервера считается завершённым отрицательным измерением; внутренняя ошибка и отмена сохраняют отдельный результат.

Публикация состояния связана с `backgroundOperationId`. Чтение статуса проецирует terminal job на незавершённую карточку, не изменяя сохранённое состояние. Неоднозначная старая локальная блокировка сохраняется. Выключенные или ещё не наступившие проверки пропускаются без нового задания.

## Проверки

- Linux: 8 сценариев фактического production cycle/coordinator/helper. Проверены пауза, отдельный executor, отсутствие nested admission, отмена и read-only projection, отрицательный результат, legacy lock, ручное выключение VPN и выбор кандидата в dry-run.
- ARM64 роутер: 7 изолированных сценариев, архив `physical-auto-jobs-20260915`. Production cycle/probe используют временные синтетические Xray и transport fixtures. Архив получен до удаления тестовых каталогов.
- Исходный воспроизводимый FAIL: `auto-switch-pause-reproducer-20260915`.

Точные хеши входов, результаты и commit фиксируются отдельно в checkpoint AUTO-JOBS-001 после завершения проверок. Не является готовым релизом. Реальное переключение/откат постоянного Xray, protected domain recovery, identity-safe init и длительный совместный прогон ещё остаются условиями приёмки.
