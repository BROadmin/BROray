## Результат выпуска

`r14c68` опубликован в Stable из байтов, прошедших воспроизводимую сборку A–D, физическое обновление и same-candidate reinstall. Единственное изменение относительно `r14c67` исправляет подпись активного канала: backend и WebUI используют фактический URL updater-v5; legacy OPKG feed не изменяется. После атомарной публикации публичные объекты повторно скачаны по HTTPS и проверены по SHA-256, а updater на физическом Keenetic подтвердил `currentCandidate=r14c68`, канал `stable` и отсутствие доступного обновления. Повторный полный reinstall после продвижения не запускался.

## Новая архитектура обновлений

- маленькая постоянная updater-v5 platform;
- неизменяемые компактные application slots;
- атомарное переключение `/opt/broray/current`;
- Xray runtime и пользовательские данные вне app-slot;
- общий транзакционный путь update/reinstall;
- проверка версии, OPKG, backend, Xray и служб после переключения;
- автоматический возврат предыдущего slot при проверяемой ошибке;
- fail-closed состояние `recovery-required`, если безопасный автоматический откат доказать нельзя.

## WebUI и производительность

- полный авторизованный интерфейс для всех основных функций;
- 12 страниц проверены последовательно;
- 162 из 162 кнопок и 165 из 165 элементов управления имеют обработчики;
- Главная обслуживается из атомарных фоновых снимков;
- тяжёлые read-only проверки имеют ограниченный срок кэша;
- скрытые вкладки не продолжают дорогой polling;
- серверный auto-switch не выполняет полный summary на каждом здоровом цикле.

## Серверы и подписки

- VLESS, VMess, Trojan и Hysteria2;
- корректное сохранение Reality fingerprint, public key, SNI, short ID, spiderX и Vision flow;
- TCP/raw и XHTTP разбираются без подмены transport;
- проверка всех серверов и свежие метрики;
- автоматический выбор резервного сервера;
- безопасное обновление подписок с сохранением активного выбора.

## Keenetic и DNS-over-TLS

- безопасное владение ProxyN без привязки к конкретному роутеру;
- пользовательское имя `BROray - <активный сервер>`;
- отдельные действия создания, восстановления и синхронизации;
- девять диагностических проверок интерфейса;
- до восьми DoT-записей с TLS/SNI-проверкой;
- внешние DoT/DoH сохраняются и не получают ложный receipt BROray;
- DNS workflow отделён от admission маршрутов.

## Маршруты

- готовые и пользовательские наборы;
- BAT читается как данные и не выполняется;
- единый реестр владельцев общих маршрутов;
- пакетная обработка больших наборов;
- rollback-intent записывается до каждой forward mutation;
- rollback использует один свежий снимок конфигурации и одну операцию save;
- volatile-заголовки Keenetic `Last change` и `Username` исключаются из сравнения, остальные байты остаются защищёнными;
- обязательный физический failpoint: ошибка после 20 из 40 добавлений, 20 обратных удалений, ноль утечек и точное исходное состояние.

## Xray

- Xray 26.7.28 при чистой установке;
- общий runtime сохраняется при update/reinstall приложения;
- запуск, остановка, перезапуск, проверка конфигурации и диагностика;
- раздельные действия обновления и переустановки;
- динамический storage admission вместо ошибочного фиксированного требования 102 МиБ.

## Обновление

Обновление поддерживается только с исправной ветки 3.x, которая уже содержит updater-v5. Для 2.x требуется чистая установка после сохранения нужных данных. См. [инструкцию](installation.md).

## Известные границы

- Поддерживается только `aarch64-3.10`.
- BROray не может восстановить маршруты, которые сам Keenetic удалил вместе с вручную удалённым прокси-интерфейсом, без отдельного подтверждённого применения наборов.
- Чужие маршруты, DNS-записи и интерфейсы не изменяются без доказанного владения.
- Документация релиза не заменяет отдельную синхронизацию точного release-source overlay с веткой GitHub.
