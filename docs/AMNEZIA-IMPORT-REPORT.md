# Отчёт: импорт AmneziaWG без подключения

Дата: 2026-11-08. Ветка: `codex/amnezia-import-only`. База: BROray 3.5.1, `b2acc8348dbee4e741f8a4c8f4fcf6ccc39bce9e`.

## Результат

В рабочем коде добавлены разбор и сохранение клиентского профиля AmneziaWG из `vpn://` вручную и из подписки. Независимый пакет `internal/amnezia` хранит версионированную модель без привязки к Xray или Keenetic. Сохраняются исходная конфигурация и неизвестные расширения. Подключение не реализовано и явно запрещено до запуска процессов: API, XrayConfig, прямые/очередные/массовые проверки, предпочтительный сервер и кандидаты автовыбора.

WebUI показывает причину недоступности подключения, запрещает «Подключить» и «Проверить», оставляет просмотр/удаление. Недоступный для проверки AWG не вызывает требование выполнить проверку качества. API summary/details не выдаёт приватную модель. Штатное резервное копирование сохраняет профиль; штатная синхронизация подписок обновляет параметры, сохраняет ID при ротации и удаляет исчезнувший AWG. Повреждённый узел остаётся причиной защиты неполной подписки от удаления несопоставленных серверов.

Изменения не опубликованы, роутеры не изменялись. Исправление идентичности VLESS/SNI и добавление других импортёров в эту правку не входят.

Локальный `git commit` не создан: Git завершился RC 128 (`Author identity unknown`), поскольку не настроены имя и email автора. Глобальная конфигурация Git не менялась, чужая авторская подпись не подставлялась. Изменения остаются подготовленными в индексе рабочей ветки; это ограничение сохранения коммита, не ошибка проверки кода.

## Обнаруженные и исправленные проблемы

- **P2, preview/persistence:** разрешённый по размеру сжатый вход мог превысить предел сохранённой модели из-за нескольких её представлений. Теперь до успеха preview проверяются 512 KiB модели и валидность записи. `amnezia-review-red` воспроизвёл исходную ошибку; финальный тест проходит.
- **P2, неоднозначный JSON:** обычный decoder перезаписывал повторные ключи. Теперь дубликаты запрещены рекурсивно, в том числе внутри JSON-строки `last_config`; добавлен предел глубины, числа сохраняют точность. Host RED → GREEN подтверждён.
- **P3, качество AWG:** сводка требовала выполнить невозможную проверку качества. Теперь статус `unsupported/not-applicable`, без `QUALITY_INCOMPLETE` для AWG. RED воспроизведён в `amnezia-review-red`, финальный тест проходит.
- **P2, браузерная форма импорта:** существующий `parseInput` отсеивал `vpn://` до запроса backend. Добавлен пропуск схемы к серверной валидации, объяснение формата, предупреждение в предварительном просмотре. Два дополнительных JS-теста подтверждают RED → GREEN: preview→save с режимом «Только сохранение» и отказ неизвестному контейнеру по ответу backend.
- При первом RED подписок была **ошибка тестовой оснастки**: создана неинициализированная metadata map, panic/RC 2 вместо ожидаемого RC 1. Сохранены `amnezia-sub-red.*`; исправлен только конструктор фикстуры. `amnezia-sub-red2.*` фиксирует настоящий RED отсутствия распознавания AWG, далее GREEN. Первый результат не заменён положительным.
- Прежние RED также показали отсутствие импорта, неподходящий код ошибки очереди, возможность выбрать AWG предпочтительным и активные кнопки UI. Соответствующие регрессии входят в финальные проверки.

Независимый рецензент выполнил read-only проверку, нашёл первые два P2 и после исправления подтвердил их закрытие. Новых замечаний по исправлениям не предъявил; тесты рецензент не запускал.

## Ограничения и дальнейшая интеграция

Текущий импорт поддерживает один контейнер AWG с готовым клиентским INI. Полные границы и матрица других протоколов: [PROTOCOL-SUPPORT.md](PROTOCOL-SUPPORT.md). Структурная валидность не означает поддержку всех AWG-опций каким-либо backend. Исходные параметры сохраняются для дальнейшей интеграции, но гарантия совместимости с ещё не существующим API Xray невозможна.

После выбора backend потребуется его адаптер, проверка поддерживаемых параметров, запуск/остановка, маршрутизация и отдельные испытания трафика. В этом изменении такие действия не выполнялись.
