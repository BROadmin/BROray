# Журнал проекта BROray

Журнал фиксирует обязательные решения, ошибки процесса, отозванные артефакты и защиту от повторения. Он не заменяет `CHANGELOG.md` и технические runtime-журналы.

## J-20260804-01 — самовольная замена архитектуры обновления

**Дата:** 2026-08-04  
**Класс:** нарушение обязательного проектного контракта  
**Критичность:** высокая  
**Статус:** архитектурная ветка отозвана; предотвращено до установки

### Событие

При разработке BROray 2.2.7 исходная схема с единственной полной копией в `/tmp` была заменена экспериментальной схемой:

```text
/opt/var/tmp/broray-transactions
/opt/var/lib/broray/scratch
/opt/broray/backup/user-data-before-...
```

Rollback IPK, candidate и отдельная копия пользовательских данных планировались на `/opt`.

### Почему это ошибка

- нарушен точный путь `/tmp/broray-update-<operation-id>/backup.tar.gz`;
- рабочие артефакты занимали пространство OPKG на `/opt`;
- одна полная точка возврата была разделена на зависимые части;
- тесты проверяли экспериментальную реализацию, а не исходный промт;
- update и reinstall расходились по последовательности;
- начальная очистка не была доказана единым контрактом.

### Фактическое воздействие

- пользователю были выданы лишние preflight-файлы;
- физический preflight показал блокировки места, созданные неверной схемой;
- пакет BROray 2.2.7 на роутер не устанавливался;
- рабочая BROray 2.2.6 и пользовательские данные не заменялись.

### Отозвано

```text
BROray-2.2.7-exact-preflight-r4.run.sh
broray_2.2.7_aarch64-3.10.ipk
ea85866086e754c5e03abbee6e33f4b0f307c26101351467dc22052f0fa34e3d
```

### Исправление

Принят `RELEASE-REQUIREMENTS.md` версии 1.7. Рабочая транзакция, единственная полная копия, previous IPK и candidate IPK размещаются только в `/tmp/broray-update-<operation-id>/`.

### Защита от повторения

- requirement IDs;
- машиночитаемая traceability matrix;
- static gate запрещённых путей `/opt`;
- тест точного порядка очистки/backup/download/install;
- release builder блокирует кандидат без доказательства каждого требования;
- архитектурное изменение возможно только новой явно утверждённой редакцией контракта.

## J-20260804-02 — повторные ложные блокировки preflight

**Класс:** регрессия совместимости BusyBox/Entware  
**Критичность:** средняя  
**Статус:** внесено в обязательный контракт 1.7

Повторно проявились ранее известные ошибки:

- `flock` считался отсутствующим из-за PATH/лишней зависимости;
- OPKG не определял версию при отсутствующем `/opt/tmp`;
- `symlinks=0` и `invalidJson=0` выводились рядом с общей ошибкой, скрывая фактический отказ сбора metadata;
- Xray искался только по полному пути процесса;
- более поздний preflight потребовал отсутствующую команду `paste`;
- WebUI ранее ошибочно проверялся через `127.0.0.1`, хотя listener находился на LAN-адресе.

Обязательные меры:

- canonical PATH `/opt/sbin:/opt/bin:/usr/sbin:/usr/bin:/sbin:/bin`;
- блокировка `mkdir`, без `flock`;
- проверка `/opt/tmp -> /tmp` до OPKG;
- отсутствие неактивного `opkg.lock` не является ошибкой;
- переносимый metadata collector с сохранённым stderr;
- устойчивые argv-сигнатуры процессов;
- WebUI проверяется по фактическому listener;
- новые команды становятся зависимостями только после package/preflight/physical-test gate.

## D-20260804-01 — утверждена улучшенная исходная схема

**Тип:** обязательное архитектурное решение  
**Статус:** принято

Исходная схема сохраняет единую полную точку возврата в `/tmp`. Из экспериментальной схемы допускаются только механизмы контроля:

- operation-id;
- atomic lock;
- sidecar-доказательства backup;
- exact previous IPK;
- сервисный snapshot;
- protected-data manifest;
- единый runner;
- persistent interruption marker;
- bounded postcheck;
- отдельные operation logs;
- requirements traceability.

## J-20260806-01 — сборщик BROray 3.0.0-r1 потребовал отсутствующий артефакт exact source

**Дата:** 2026-08-06  
**Класс:** рассинхронизация release builder с exact source 2.2.7-r26  
**Критичность:** высокая  
**Статус:** builder r1 отозван; кандидат 3.0.0-r1 не создан и не опубликован

### Событие

Первый запуск `BROray-3.0.0-r1-build-publish-r1.sh` на релизном сервере прошёл проверку собственного размера, SHA-256 и синтаксиса, нашёл точный source/rollback `broray_2.2.7-r26_aarch64-3.10.ipk`, извлёк пакет и остановился на этапе 2:

```text
ОШИБКА: не найден обычный файл:
/tmp/broray-300-r1-build.MsAZTT/tree/data/opt/broray/share/release/package-space.json
```

Рабочий каталог сохранён:

```text
/tmp/broray-300-r1-build.MsAZTT
```

### Подтверждённая причина

Сборщик безусловно включил файл:

```text
/opt/broray/share/release/package-space.json
```

в список обязательных файлов exact r26. В извлечённом опубликованном IPK r26 этот путь отсутствовал. Сборщик не имел права считать его обязательной частью source-контракта без предварительного подтверждения фактического состава exact IPK.

### Фактическое воздействие

- новый IPK 3.0.0-r1 не собирался;
- updater и `release.json` 3.0.0-r1 не создавались;
- staging 3.0.0-r1 не публиковался;
- stable не изменялся;
- exact r26 не изменялся;
- на Keenetic никаких действий не выполнялось.

### Отозвано

```text
BROray-3.0.0-r1-build-publish-r1.sh
SHA-256: 35ab785ce5b79f755971db88adb4ca2a542ccff9e5733a1e066f0291c6c4d9c3
```

### Защита от повторения

- до любой мутации извлекать exact source и формировать фактический source-tree manifest;
- разделять обязательные source-файлы и создаваемые target-файлы;
- `package-space.json` считать входным артефактом только при доказанном наличии и валидности;
- при отсутствии исходного `package-space.json` генерировать канонический target-файл из фактического IPK и расчёта транзакции;
- добавить отрицательный тест exact source без `package-space.json`;
- новый сборщик выпускать только под новым revision имени, без перезаписи r1.

## J-20260806-02 — предвыдачная валидация 3.0.0-r1 не соответствовала реальному exact source

**Дата:** 2026-08-06  
**Класс:** ложноположительный release gate / недостаточная проверка доказательств  
**Критичность:** высокая  
**Статус:** прежний validation report не является доказательством готовности к сборке

### Событие

До серверного запуска было заявлено, что сборщик 3.0.0-r1 прошёл полный изолированный выпуск, A/B/C-сборку, холодное извлечение и публикационную модель. Реальный запуск на точном опубликованном r26 остановился до формирования target-дерева из-за отсутствующего `package-space.json`.

### Почему это отдельная ошибка процесса

- лабораторная модель не воспроизводила фактическую структуру exact r26;
- synthetic fixture содержала артефакт или допущение, которого не было в реальном source IPK;
- проверялась внутренняя согласованность модели, но не совместимость с точными опубликованными байтами источника;
- формулировка «подготовлен финальный сборщик» и перечисленные `PASS` были сильнее фактически полученных доказательств.

### Защита от повторения

- финальный builder-gate обязан запускаться на копии точного опубликованного source IPK с его закреплённым SHA-256;
- validation report обязан перечислять фактически найденные и отсутствующие source paths;
- модель не может создавать отсутствующие source-файлы до прохождения source-contract gate;
- успешный модельный тест помечается как лабораторный и не заменяет реальный серверный build gate;
- до полного серверного финального блока запрещено называть артефакт готовым кандидатом;
- расхождение модели с exact source автоматически отзывает builder и его validation report.

## Следующее обязательное действие проекта

Подготовить новый immutable builder BROray 3.0.0-r1 с новым revision имени, который:

1. использует exact опубликованный r26 как source и rollback;
2. сначала фиксирует реальный состав source IPK;
3. не требует отсутствующий `package-space.json`;
4. генерирует target space metadata из фактических данных;
5. проходит отрицательный тест source без `package-space.json`;
6. только после полного серверного финального блока допускается к физическому испытанию Keenetic.

До этого stable и Keenetic не изменяются.
