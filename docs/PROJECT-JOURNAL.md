# Журнал проекта BROray

Журнал фиксирует обязательные решения, ошибки процесса, отозванные артефакты и защиту от повторения. Он не заменяет `CHANGELOG.md` и технические runtime-журналы.

## J-20260804-01 — самовольная замена архитектуры обновления

**Дата:** 2026-08-04  
**Класс:** нарушение обязательного проектного контракта  
**Критичность:** высокая  
**Статус:** архитектурная ветка отозвана; предотвращено до установки

### Событие

При разработке BROray 2.2.7 исходная схема с единственной полной копией в `/tmp` была заменена экспериментальной схемой:

```text
/opt/var/tmp/broray-transactions
/opt/var/lib/broray/scratch
/opt/broray/backup/user-data-before-...
```

Rollback IPK, candidate и отдельная копия пользовательских данных планировались на `/opt`.

### Почему это ошибка

- нарушен точный путь `/tmp/broray-update-<operation-id>/backup.tar.gz`;
- рабочие артефакты занимали пространство OPKG на `/opt`;
- одна полная точка возврата была разделена на зависимые части;
- тесты проверяли экспериментальную реализацию, а не исходный промт;
- update и reinstall расходились по последовательности;
- начальная очистка не была доказана единым контрактом.

### Фактическое воздействие

- пользователю были выданы лишние preflight-файлы;
- физический preflight показал блокировки места, созданные неверной схемой;
- пакет BROray 2.2.7 на роутер не устанавливался;
- рабочая BROray 2.2.6 и пользовательские данные не заменялись.

### Отозвано

```text
BROray-2.2.7-exact-preflight-r4.run.sh
broray_2.2.7_aarch64-3.10.ipk
ea85866086e754c5e03abbee6e33f4b0f307c26101351467dc22052f0fa34e3d
```

### Исправление

Принят `RELEASE-REQUIREMENTS.md` версии 1.7. Рабочая транзакция, единственная полная копия, previous IPK и candidate IPK размещаются только в `/tmp/broray-update-<operation-id>/`.

### Защита от повторения

- requirement IDs;
- машиночитаемая traceability matrix;
- static gate запрещённых путей `/opt`;
- тест точного порядка очистки/backup/download/install;
- release builder блокирует кандидат без доказательства каждого требования;
- архитектурное изменение возможно только новой явно утверждённой редакцией контракта.

## J-20260804-02 — повторные ложные блокировки preflight

**Класс:** регрессия совместимости BusyBox/Entware  
**Критичность:** средняя  
**Статус:** внесено в обязательный контракт 1.7

Повторно проявились ранее известные ошибки:

- `flock` считался отсутствующим из-за PATH/лишней зависимости;
- OPKG не определял версию при отсутствующем `/opt/tmp`;
- `symlinks=0` и `invalidJson=0` выводились рядом с общей ошибкой, скрывая фактический отказ сбора metadata;
- Xray искался только по полному пути процесса;
- более поздний preflight потребовал отсутствующую команду `paste`;
- WebUI ранее ошибочно проверялся через `127.0.0.1`, хотя listener находился на LAN-адресе.

Обязательные меры:

- canonical PATH `/opt/sbin:/opt/bin:/usr/sbin:/usr/bin:/sbin:/bin`;
- блокировка `mkdir`, без `flock`;
- проверка `/opt/tmp -> /tmp` до OPKG;
- отсутствие неактивного `opkg.lock` не является ошибкой;
- переносимый metadata collector с сохранённым stderr;
- устойчивые argv-сигнатуры процессов;
- WebUI проверяется по фактическому listener;
- новые команды становятся зависимостями только после package/preflight/physical-test gate.

## D-20260804-01 — утверждена улучшенная исходная схема

**Тип:** обязательное архитектурное решение  
**Статус:** принято

Исходная схема сохраняет единую полную точку возврата в `/tmp`. Из экспериментальной схемы допускаются только механизмы контроля:

- operation-id;
- atomic lock;
- sidecar-доказательства backup;
- exact previous IPK;
- сервисный snapshot;
- protected-data manifest;
- единый runner;
- persistent interruption marker;
- bounded postcheck;
- отдельные operation logs;
- requirements traceability.

## Следующее обязательное действие проекта

Перестроить код BROray 2.2.7 по версии 1.7, затем выполнить:

1. статическую трассировку всех требований;
2. детерминированную сборку;
3. лабораторную матрицу update/reinstall/rollback;
4. read-only preflight физического Keenetic Peak KN-2710;
5. canary через WebUI неизменяемыми байтами;
6. повторный полный gate перед публикацией.
