# HOME-REFRESH-001 — обновление сводки Главной

## Область изменения

Закрывается клиентский дефект HOME-01 из аудита WebUI 3.1.1: сводка
загружалась один раз и не обновлялась ни кнопкой, ни при возврате на вкладку.
Меняется только `runtime/app/web-new/assets/js/home.js`.
HTML, CSS, меню, авторизация на сервере, snapshot workers, updater,
координатор операций и конфигурация роутера не изменяются.

Исходный полный `home.js`:
- Git blob `12ba46ddc136bf2ca5342ac2d2876154c6af236b`;
- SHA-256 `78f9a5db0a3ba1626c88f550a8ce13e2d3c6b5f4d08952db1cc5d2a082f01e30`;
- база аудита `b8aab47470d8a0cdee39be374c349723aac176e0`;
- также сверено с локальным `725c53f3ae2077e9f1abb8db0129554abc59c320`.

## Поведение

1. Существующая кнопка «Обновить» становится видимой и доступной с клавиатуры.
   Значок и вложенное содержимое не заменяются. На время запроса кнопка
   блокируется, выставляются `aria-busy` и доступная подпись.
2. В видимой вкладке выполняется один повторный GET сводки через 30 секунд
   после завершения предыдущего запроса. Это не setInterval и не очередь
   накопленных тиков. Параллельные запросы этой страницы не создаются.
3. В скрытой вкладке таймер отключён, текущий запрос прерывается. Возврат
   на вкладку запускает получение сводки. Результат отменённого запроса
   не может перезаписать более новый результат или отправить на вход.
4. `pagehide` приостанавливает цикл; `pageshow` с `persisted=true`
   восстанавливает его с повторной проверкой сессии. Событие `online`
   позволяет повторить чтение; `navigator.onLine` не используется как запрет
   доступа к локальному роутеру.
5. Общий тайм-аут цикла — 15 секунд, включая проверку сессии при необходимости,
   получение заголовков и чтение JSON. AbortController отменяет запрос;
   отдельный Promise завершает ожидание интерфейса даже при позднем ответе.
6. Ошибки увеличивают интервал автоматического повтора: 30, 60, 120 секунд,
   далее максимум 120. Успех возвращает интервал 30 секунд. Кнопка ручного
   обновления доступна и между попытками; частые клики во время запроса
   не создают новые запросы.
7. HTTP 401 проверяется до JSON. Даже HTML-ответ 401 завершает цикл,
   скрывает защищённое содержимое и отправляет на существующую страницу входа.
   Нажатие «Выйти» прекращает опрос, не заменяя штатный обработчик выхода.
8. Ошибка связи/JSON сохраняет последний корректный снимок и его время.
   Отдельное сообщение прямо указывает, что данные не обновлены.
   Следующий корректный ответ убирает только сообщение об ошибке получения;
   предупреждения модулей, возвращённые сервером, сохраняются.
9. При валидном ответе с отсутствующим (`null`) модулем старые счётчики этого
   модуля очищаются до «—». Нельзя показывать прежнее значение как новое или
   подменять неизвестное состояние нулём.
10. Нет периодических success-toast. Подтверждение выводится только после
    успешного ручного обновления. Отказ старого браузера без AbortController
    не запускает неконтролируемые запросы.

## Семантика актуальности

`/api/home/summary.cgi` — существующее cache-only представление. Его GET
не выполняет прямые пробы сервисов и роутера. Исправление не добавляет
параметры force, новые endpoint, POST, shell-команды или фоновые службы.
`updatedAt` — время формирования сводки, а не доказательство свежести каждого
снимка модуля. Статусы `health`, включая предупреждения stale/expired,
отображаются в прежней семантике. Чтение свежего HTTP-ответа не превращает
предупреждение модуля в «Система работает».

30 секунд — интервал для одной открытой видимой страницы. Общий лидер
между вкладками не добавляется. Точность таймеров зависит от браузера/сна ОС;
код не заявляет реального времени. Прекращение fetch не гарантирует остановку
уже исполняющегося CGI на сервере; здесь CGI только читает локальные снимки.

## Проверки

`node --test tests/test_home_refresh.mjs` выполняет весь изменённый home.js
в VM с явными фикстурами DOM/часов/HTTP. Проверяются 42 сценария.
Те же три регрессионных требования с исходным home.js воспроизводят HOME-01.

`python tests/test_home_refresh_browser.py` — 9 проверок настоящего Chromium DOM,
кнопок и клавиатуры на статической разметке home.html. Все fetch — явные
in-memory фикстуры; сторонние скрипты, CSS и изображения не загружаются.
Перевод страницы на URL запрещён политикой среды тестирования, поэтому тест
не меняет политику браузера и работает через set_content без сети.
Это НЕ визуальная приёмка вёрстки и НЕ интеграция полного WebUI.
Перенаправление 401 и жизненный цикл вкладок проверены в VM; физическая
авторизация и настоящий bfcache требуют отдельной приёмки кандидата.

Зависимости разработки: Node.js, Python 3 и Playwright с Chromium для DOM-тестов.
Новых зависимостей на роутере нет. Тесты ничего не устанавливают.

## Оставшаяся приёмка

На собранном кандидате проверить исходную тему и мобильную ширину с полными
CSS/JS; совместную работу app-shell и выхода; локальный и KeenDNS доступ;
обновление после реальной смены активного сервера и подписки; реальный 401;
возврат из фоновой вкладки и bfcache; сохранение warnings устаревших снимков.
Не объявлять эти пункты пройденными по VM или in-memory HTTP тестам.
