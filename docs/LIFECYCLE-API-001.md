# BROray 3.1.1: жизненный цикл, API и интерфейс

Состояние 15 сентября 2026 года: промежуточная проверенная реализация. Установочный кандидат и релиз ещё не сформированы. На роутере запускались только изолированные проверки; службы BROray не установлены.

## Выполнено

- Русская подпись «Не в каталоге BROray». Дублирующий бейдж «Член каталога: да/нет» удалён. Длинные подписи и адреса переносятся в DNS-карточках.
- Клиент сохраняет nonce запуска; повтор возвращает ту же операцию. Отдельное идемпотентное подтверждение требуется до работы. Не подтверждённые операции с отсутствующим владельцем восстанавливаются, в том числе без опубликованного fence.
- Повтор завершения сохраняет прежний результат и не удаляет блокировку следующей операции. Повтор отмены не дублирует событие.
- Переход к записи сериализован с отменой: ранее принятая отмена запрещает вход в commit; начатый commit защищён от отмены.
- Heartbeat хранится в RAM. Повтор heartbeat в той же фазе не меняет persistent state/revision и журнал.
- Native guard v3 сохраняет временный файл через fsync, атомарно заменяет state и выполняет fsync родительского каталога до успешного ответа. Симлинки, hardlink и публичные права файла отвергаются.
- Менеджер хранения подключает клиент; старое удаление истории пропускает новые и повреждённые записи. Новый координатор хранит минимум двадцать последних завершённых операций, сохраняя live/ambiguous owners и непроверенных children.
- CGI status/events/report/cancel/stop-background/recover/automation используют существующую проверку сессии. POST требует точный Origin и специальный заголовок; JSON ограничен 4 КБ и набором разрешённых полей. GET не восстанавливает и не меняет операции.
- Диагностика собирает ограниченный снимок через allowlist. Недоступные сведения явно отмечены. Отчёт пока не определяет идентичности служб, KeeneticOS, kernel, настройки каждого вида автоматики и непрерывность VPN.
- Журнал отмечает повреждённые строки и обнаруженные ошибки записи; его ошибка не удерживает подтверждённо завершённую блокировку.
- Основная страница BROray содержит блоки операций, паузы автоматики, журнала, копирования и скачивания отчёта; потеря связи сохраняет последние данные с отметкой устаревания.

## Открытые условия релиза

1. Управляемый запуск children до допуска к работе, доказательство отсутствия потомков и безопасная эскалация TERM/KILL. Новое ядро пока не имеет этих API или runner; записи children применялись только как тестовые fixtures.
2. Отдельный owner каждого scheduler job; подключение всех producers одновременно, включая subscription merge, auto-check/auto-switch, async Xray handoff, resumable routes и boot recovery. Новые CGI/UI не делают старые producers управляемыми.
3. Полный протокол legacy recovery и доставка на 3.1.0, чей updater отвергает запрос до загрузки нового кода. Не заменять этот сценарий ручным удалением lock или обязательной перезагрузкой.
4. Дополнительная устойчивость журнала к потере последней записи при выключении питания, последовательность событий и все реальные emitters; проверка ENOSPC на реальной файловой системе.
5. Установочный builder, candidate/version identity, подпись, сохранность данных и полный upgrade/reinstall/rollback.
6. Реальные VPN continuity, конкуренция, crash/reboot/power-loss, ускоренные циклы и 72 часа combined automation. Эти проверки не выполнялись.

Техническая база для следующего child runner: [waitid/WNOWAIT](https://man7.org/linux/man-pages/man2/waitpid.2.html), [subreaper](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html), [setsid](https://man7.org/linux/man-pages/man2/setsid.2.html). Владение своим неубранным child отличается от повторной проверки чужого числового PID. Пока runner не реализован и не проверен, это направление работы, а не гарантия безопасной остановки.
