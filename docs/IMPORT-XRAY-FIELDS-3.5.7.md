## Candidate4 account-level correction

The pinned [DefaultManager](https://github.com/XTLS/Xray-core/blob/676eaf66f8f05d4d558ee7a74b4736623d3feeb9/features/policy/default.go#L16) accepts every protocol-valid account level when BROray emits no root policy. It uses the ordinary 300-second idle default except level 1, whose idle default is 600 seconds. This is distinct from the [configured policy manager](https://github.com/XTLS/Xray-core/blob/676eaf66f8f05d4d558ee7a74b4736623d3feeb9/app/policy/manager.go), whose absent entries all fall back to SessionDefault. Valid nonzero account levels therefore do not require importing a provider's process policy.

Exact account levels are retained privately and emitted. Display grouping treats 0/8/maximum as default-equivalent, retaining the authenticated level-1 distinction. Flat HTTP/SOCKS without a username creates no account; an explicit legacy empty account is preserved. The [SS2022 builder](https://github.com/XTLS/Xray-core/blob/676eaf66f8f05d4d558ee7a74b4736623d3feeb9/infra/conf/shadowsocks.go#L230) ignores level/email even though BROray preserves them, so all its levels are display-equivalent and an explicit warning explains the effect. Trojan/SS byte bounds remain 0..255; the other four ordinary account protocols use uint32.

Existing C3 private wrappers whose only obsolete dependency was a nonzero account level remain readable/restorable and disabled after complete projection validation. Explicit subscription refresh or reimport creates the now-supported ordinary record. This compatibility rule does not activate a server or admit malformed data.
