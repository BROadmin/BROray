# BROray 3.5.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Этот документ не запускает реализацию или делегирование.

**Goal:** Принять Xray 26.11.9, устранить потерю/искажение параметров импорта, добавить XDRIVE и MASQUE и выпустить проверенную 3.5.3 с обновлением от 3.5.0.

**Architecture:** Сохраняются Record и существующие службы BROray. Общие правила нормализации и проверки используются URI- и JSON-импортом; новые протоколы имеют отдельные валидаторы и генераторы. Родной JSON новых транспортов преобразуется в типизированную запись напрямую, без выдуманного промежуточного URI. Старые записи читаются совместимо, требования к ядру проверяются перед подключением и понижением версии.

**Tech Stack:** Go с текущими vendor-зависимостями и зафиксированным проверенным toolchain проекта; существующий JavaScript WebUI и Node-тесты; официальный Xray 26.11.9; Linux VM/QEMU и тестовый Keenetic. Новые зависимости добавлять только при доказанной необходимости.

**Spec:** [Требования 3.5.3](../specs/2026-11-10-release-353.md).

## Global Constraints

- Решение владельца 10 ноября 2026: продолжать с явным ограничением WireGuard на MIPS/MIPS LE. Сохранить FAIL, принять только проверенную положительную часть; остальные этапы и требования сохраняются. Это согласованное исключение CORE-353-WG-MIPS, не полная совместимость и не аппаратный вывод.

- Основа кода: `b66eb60bcaa56fe5041a19df8efe60e6d07b18c0`; схемы ядра: `v26.11.9`. Четыре архитектуры: aarch64, ARMv7, MIPS little-endian, MIPS big-endian.
- Переход 3.5.0/3.5.1/3.5.2 → 3.5.3 сохраняет данные; с 3.2 требуется чистая установка.
- Повторный вход после обновления, маршруты без `auto`, TCP-only с предупреждением без UDP ProxyN остаются согласованным поведением.
- AWG — только хранение. Полные чужие routing/DNS/inbound/API не исполняются. Исходники опубликованных выпусков и их архивы не переписываются.
- Для каждого найденного дефекта: отдельный подтверждающий RED, минимальное исправление, GREEN. Первый результат сохраняется. Ошибка оснастки не превращается в продуктовый PASS.
- Секреты и реальные ссылки не попадают в тестовые fixture, Git, отчёты и публичную диагностику. В тестах используются синтетические значения.
- Новое ядро не подменяется автоматически при обновлении BROray; функции, требующие нового ядра, объясняют это до сохранения/подключения согласно матрице возможностей.
- Выпуск собирается после объединения исправлений. Повторять пройденную проверку только после затрагивающего её изменения; не создавать кандидата на каждую кнопку/находку.

## Review Focus

- Конфликт альтернативных имён и неверно размещённое поле должны давать ошибку до изменения каталога — Task 2.
- `false`, `0`, пустое/отсутствующее значение, сохранение/backup и повторный импорт не меняют смысл — Tasks 2–3.
- Частично разобранная подписка и смена SNI/ShortID не удаляют рабочие узлы и не смешивают источники — Task 3.
- Облачные ключи, заголовки Authorization и вложенные расширения не раскрываются через ошибки/API/backup preview — Tasks 4–6.
- Старое ядро, отказ облака и неудачное обновление сохраняют управление и согласованное восстановление — Tasks 1, 4, 7–8.
