# Доставка recovery на уже заблокированную 3.1.0

15 сентября 2026. Статус: исследование, штатный GUI-путь для целевой версии ещё не подтверждён. Никакие настройки или компоненты Keenetic не изменялись.

## Что подтверждено

- Исходный updater 3.1.0 проверяет conflicting operation до получения нового приложения. Поэтому новый coordinator внутри ещё не установленной 3.1.1 не может исправить admission старого updater.
- На тестовом устройстве read-only `show version` сообщил `5.01.C.4.0-1`, `Peak (KN-2710)`. Kernel `4.9-ndm-5` не является номером KeeneticOS; их нельзя смешивать в диагностике.
- В документации Keenetic описан Web CLI по пути `/a`, но прямо указано, что это неполный командный интерфейс и некоторые команды там недоступны. Статья не доказывает запуск Entware recovery через него. [Command-line interface](https://support.keenetic.com/eu/challenger/kn-3910/en/18480-command-line-interface--cli-.html).
- Обычный CLI поддерживает `exec sh` после установки Entware. Официальная инструкция показывает именно CLI, а не подтверждённый запуск из старого Web CLI. [Установка Entware во внутреннюю память](https://support.keenetic.com/peak/kn-2710/en/18482-installing-opkg-entware-in-the-router-s-internal-memory.html).
- Полноценная browser shell заявлена как новый компонент в KeeneticOS 5.2 Alpha 1 от 18 июля 2026. Это отдельная возможность другой версии; она не подтверждает её наличие на целевой 5.1. Обновление ОС/обязательная перезагрузка не принимаются за готовое recovery-решение этого дефекта. [KeeneticOS 5.2 release notes](https://support.keenetic.com/stellar-6/kap-650/en/53529-latest-development-release.html).

## Остаётся проверить

1. Фактическая возможность безопасного запуска подписанного одноразового bootstrap через доступный интерфейс Keenetic 5.1. Нужна безвредная marker-проба, прежде чем проектировать пользовательский сценарий.
2. Если интерфейс не позволяет доставить код, отдельно обосновать минимальный пользовательский recovery-инструмент. Не объявлять существующим интерфейс, которого нет, и не заменять результат инструкцией ручного `rm lock`.
3. Сам recovery должен доказать quiescence legacy producers и сохранность постоянного Xray. Новый native supervisor управляет только своими fork descendants; это **не** разрешение применять его сигналы к PID из старых lock-файлов.

Поиск сначала выполнен через Firecrawl Developer Index. Общий Firecrawl search вернул HTTP 402; первичные страницы затем проверены обычным web search. Старые URL help.keenetic.com теперь могут перенаправлять на общий support.keenetic.com; ссылки выше указывают на найденные страницы документации.
