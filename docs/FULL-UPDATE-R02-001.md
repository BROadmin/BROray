# Подписанное обновление r01c01 → r02c01 через WebUI

Физический Keenetic Peak KN-2710, KeeneticOS 5.01.C.4.0-1. Новый archive SHA-256 `8056e96c1dc600941fe2f3031e678e1b5d8e5b335896b06aa71356b1f8fabcf7`, 2 064 813 байт, runtime из `1024e6c968b63e6e15744a5d537d94405c5a9473`. Сборка побайтово повторяема; штатный minisign key не заменялся.

Индекс и архив размещены только в новом immutable staging-каталоге r02c01. Все четыре файла проверены внешним HTTPS-клиентом в обычном режиме и с no-cache: HTTP 200, точные размеры и SHA. Снимки файлов stable до/после совпали. На роутере штатные updater validator и native minisign приняли подпись, дерево, метрики и синтаксис; неподписанное изменение индекса и ошибочный старый test descriptor отклонены.

Пользовательский путь выполнен в настоящем браузере: BROray → Проверить обновление → Установить обновление → Установить. Операция `update-20260915221128-17340` завершилась success/complete/100%, rollback не выполнялся. Страница автоматически переждала остановку WebUI и показала r02c01 и «Завершено» без ручного обновления страницы.

После обновления подтверждены все checksums current, OPKG metadata, Xray 26.9.9/config, S22/S23/S24/S25/S28 и намеренно остановленная auto-switch. Общая пауза сохранилась. Полный перечень файлов config/servers/subscriptions и их hashes совпал. Running/startup конфигурации совпали после исключения только экспортных метаданных ndmc (время/контрольная сумма/имя экспортирующего клиента). Настройки доступа не менялись.

## Контролируемый переход со старого S24

Установленный r01c01 ещё использовал старую остановку home-snapshot по PID. Перед обновлением внешняя init-ссылка временно заменена строго привязанной обёрткой; файлы slot не изменялись. Обёртка разрешала переход только из дочернего вызова подтверждённого updater с request fence, для точного SHA старого S24 и при отсутствии legacy reconcile PID.

Отдельный **тестовый**, не включённый в release runtime helper проверяет PID, start ticks, boot, exe и точные NUL-argv, закрепляет single-threaded shell через ptrace, повторяет проверку и требует единственного дочернего BusyBox sleep. Затем завершает закреплённый shell без старого PID-based trap; sleep заканчивается естественно. Многопоточный процесс, другой daemon, активный/multiple child или неполная identity отвергаются. 6 Linux и 2 physical fixture проверки PASS. На установленном legacy home этот переход завершился; identity постоянного Xray до/после совпала. Позднее штатный updater намеренно перезапустил Xray при замене слота.

После полной проверки результата оригинальная S24-ссылка восстановлена под coordinator admission. Временный namespace заархивирован и удалён после проверки отсутствия процессов из него. Это scoped test migration, **не подтверждение публичного recovery заблокированной 3.1.0** и не доказательство quiescence всех legacy producers.

## Сохранённые ошибки тестового harness

Первый setup остановился: временный channel-файл имел 0644, а durable publisher требует 0600. Protected fence сохранился. После проверки точного частичного состояния завершена именно эта доменная работа и использован исходный capability token для штатного finish; ручного удаления lock не было. Второй harness ожидал несуществующее значение globalFence=none вместо контрактного absent; исправлено только ожидание, обязательная проверка повторилась с PASS.

Evidence: `full-update-r02c01-20260916`, `signed-candidate-validator-20260916`, `staging-r02c01-20260916`, `physical-idle-quiescence-20260916`. Приватные конфигурации — `.private/router-update-r02c01-20260916/`.

Релиз не готов: переустановка, rollback/fault matrix, полный набор producers/domain recovery, VPN, reboot/power-loss, UI matrix и endurance остаются отдельными gate. Сохраняется ROOT_CAUSE_NOT_PROVEN исходного пользовательского инцидента.
