# ROUTES-SYNC-BUNDLE-001 — передача ID набора в ресурсную блокировку

## Область исправления

Этап 02 аудита WebUI BROray 3.1.1. Исходная публичная база:
`b8aab47470d8a0cdee39be374c349723aac176e0`. Локальный проверенный ref:
`725c53f3ae2077e9f1abb8db0129554abc59c320` на
`codex/broray-3.1.1-operations`. Рабочая ветка при подготовке не менялась.

Точечная правка касается `runtime/app/lib/routes-router-sync.sh`, а не
исторического `root/`. Она передаёт `${BRORAY_SYNC_BUNDLE:-}` вместо пустой
строки в `broray_route_resource_acquire` для операции `sync`.

## Причина

`broray_routes_sync_plan` и `broray_routes_sync_apply` уже проверяют аргумент
набора и до захвата блокировки присваивают и экспортируют `BRORAY_SYNC_BUNDLE`.
Однако обёртка `broray_routes_sync_lock_acquire` теряла этот ID, передавая `""`.

Неизменённый `routes-resource-control.sh` для защищённой операции требует
`.bundleId == $bundle`. При непустом ID задания и пустом ID ресурса предикат
возвращает отказ 73. Неизменённый `routes-resource-lock.sh` преобразует его в 1,
и построение плана прерывается сообщением «Не удалось установить блокировку
операции.». Это не основание удалять блокировку или ослаблять проверку.

Путь готовых наборов: `verify.cgi` → `broray-routes plan` → sync plan.
Путь пользовательских наборов: `preflight.cgi` с `action=export` →
`broray-routes plan` → тот же sync plan. На обоих путях найдена одна общая
несостыковка. Без физического повтора нельзя утверждать, что у прежних
наблюдавшихся отказов нет других причин.

## Что не меняется

Проверка сессии, логическое разрешение задания, ptrace-membership, токен и
полная идентичность владельца, проверка чужих/неоднозначных файлов, правила
освобождения ресурса, rollback-маркеры, отмена/возобновление, реестр маршрутов,
сам алгоритм установки, протокол записи Keenetic и updater не меняются.

Отдельный несупервизируемый вызов без BRORAY_SYNC_BUNDLE по-прежнему передаёт
пустое значение. Защищённый вызов с отсутствующим или чужим ID по-прежнему
отклоняется. Наличие переменной не заменяет действующую проверку участника
защищённого дерева процессов.

## Готовые проверки

`tests/test_routes_sync_bundle_contract.py` исполняет реальные извлечённые
функции проверки ID, захвата/освобождения и sync plan, а также точный jq-предикат
допуска и таблицу преобразования кода возврата из исходников. Точки извлечения
должны находиться ровно один раз, иначе тест завершается ошибкой.

26 тестов проверяют передачу ID для готового и пользовательского набора,
контексты plan/verify/preflight/export/resume на границе блокировки, чужой и
отсутствующий ID, старый ID в переменной, последовательные планы, старую
standalone-совместимость, передачу кодов отказа, локальные токен/held-поля,
существующую валидацию ID и запрет плана при rollback-маркере.

Это CONTRACT/UNIT-тесты. Координатор, проверка членства, native guard, хранение
блокировок, вычисление плана, cleanup и abort/rollback — тестовые заглушки.
Положительный тест не доказывает реальное HTTP 200, установку маршрутов,
освобождение native lease или сохранность физической конфигурации роутера.

В пакете `captured/` содержит только обозначенные точные фрагменты исходников,
не полные файлы. Они предназначены исключительно для повторения локального
контрактного теста. Копировать их в runtime запрещено. Полный исходный файл
85 КБ заменяется не ими, а однострочным патчем после проверки Git blob.

## Обязательная интеграционная приёмка кандидата

В штатной изолированной Linux-среде проекта выполнить существующие тесты
ресурсных блокировок, защищённых route jobs, CGI/CLI и восстановления, а не
заменять их новыми контрактными тестами. Проверить реальные native guard,
координатор, подсистему регистрации дочерних процессов и policy чтения Keenetic.

На разрешённом тестовом роутере, после определения свободного candidate ID и
сборки штатным builder, отдельно проверить:

1. Готовый Telegram: скачивание → verify → preflight → подтверждённая установка
   → сверка фактических маршрутов → удаление только тестовых маршрутов.
2. Пользовательский BAT из TEST-NET: импорт → preflight → установка → сверка
   → контролируемая очистка временного набора.
3. Пока идёт чужая конфликтующая операция, новая операция отклоняется без
   изменения её файлов; собственная завершённая операция не оставляет блокировку.
4. Сохранность внешних маршрутов, других наборов, паузы автоматики и доступа;
   отказ чтения конфигурации и незавершённый rollback не превращаются в успех.

Остановка/перезапуск/обновление BROray, системные сетевые настройки и публикация
stable не входят в разрешения этого пакета. Физические тесты здесь NOT_RUN.
