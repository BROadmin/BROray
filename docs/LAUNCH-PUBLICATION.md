# Атомарная публикация запуска и потеря ответа

Промежуточный этап BROray 3.1.1. Полное приложение на роутер не установлено; подключение producers и приёмка релиза остаются впереди.

## Контракт запуска

Координатор готовит owner, state и fence в закрытом `.launch-PID-NONCE`. Только полностью подготовленный каталог переименовывается в публичный operation ID. Native publisher выполняет fsync подготовленных файлов и каталогов перед admission. Отдельное подтверждение клиента по-прежнему обязательно до работы.

После смерти координатора следующий begin удаляет только распознанные незавершённые staging-каталоги под эксклюзивным kernel guard. Подтверждённые операции, посторонние объекты, symlink и hardlink сохраняются. Лимит обхода — 128 каталогов. Read-only status не ремонтирует staging. Полный публичный каталог без fence повторно публикуется по тому же launch nonce.

Нулевой код транспорта с пустым, обрезанным или некорректным успешным JSON считается потерянным ответом. Begin и handoff повторяются с прежними идентификаторами. Клиент принимает ID/token только вместе из единственного корректного ответа. Если все ответы потеряны, gate остаётся закрытым. Успешный повтор handoff не возвращает старому caller authority.

## Проверки и совместимость

- В Linux coordinator действительно завершает себя SIGKILL на пяти границах публикации. Executor identity в этих пяти cases моделируется. Остальные staging cases проверяют сохранение чужих объектов.
- Отдельная suite ответа использует настоящие shell owners и coordinator; shim отбрасывает ответ **после** durable mutation, в том числе при exit code 0.
- На физическом Peak KN-2710 проверены 17 сценариев: пять crash boundaries, чужой файл/symlink/hardlink, четыре ответа begin, по два ответа handoff/accept-handoff, полная потеря ответов. Все PASS; namespace архивирован и удалён.
- Первая физическая попытка обнаружила отсутствие `stat -c` в чистом Entware. Проверка числа ссылок заменена на `find -maxdepth 0 -type f -links 1`; повторные попытки сохранены отдельно. Native binaries не менялись.
- Итоговый Linux-прогон — 29 PASS за 261,81 с: launch publication 8, client responses 10, actual handoff 3, native/coordinator integration 8. Runtime hashes совпадают с этим этапом и физическим payload.
- Предыдущий широкий прогон содержит 105 PASS в гостевом console log и нормальный shutdown marker. Windows отказала в запуске `qemu --version` при оформлении host report. Исходные log/manifest сохранены в `../../docs/evidence/launch-precompat-linux-20260915`; ненаблюдавшиеся exit code/elapsed time хоста не восстановлены предположениями. Этот прогон предшествует поправке `find` и validator ответа.
- После восстановления среды подтверждён запуск PowerShell/Python/Node/QEMU и SSH. Сборщик теперь считывает version/manifest перед стартом, сверяет kernel/initramfs hashes и сохраняет фактический QEMU exit code вместе с отчётом. Source checks: 208 shell, 36 JSON, 29 JavaScript; 295 из 299 исходных baseline files не изменены.

## Границы доказательства

Проверки self-KILL не эквивалентны выключению питания. Не проверены установка приложения, его службы, рабочий Xray/VPN, upgrade/reinstall/rollback и длительный combined automation. Наличие API/UI не означает, что старые producers уже управляются новым координатором.

Отдельный следующий аудит: смерть shell coordinator во время выполнения дочернего native `--replace-file`/`--publish-fence`. Текущий guard использует process-associated `F_SETLK`; уже проведённые crash hooks срабатывают после завершения этих команд. Сохранение исключительного доступа при оставшемся дочернем writer ещё не доказано и должно быть проверено до producer rollout.

При первом открытии `http://192.168.1.1/a` браузер показал сообщение об управлении провайдером без формы входа. Пользователь сообщил, что вошёл в роутер. После открытия главной страницы и завершения загрузки подтверждена обычная форма входа. Преждевременный вывод об ограничении доступа снят; настройки Keenetic не менялись. Оба наблюдения сохранены в `../../docs/evidence/keenetic-web-access-20260915*.json`. WebCLI bootstrap ещё не проверен; агент пока не авторизован в отдельной браузерной сессии.
