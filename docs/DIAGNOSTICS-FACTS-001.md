# Диагностика: ограниченное чтение фактических настроек

Исходный дефект воспроизведён до изменения production: при достоверном `enabled:false` отчёт возвращал `autoSwitch:null`. Evidence: `docs/evidence/diagnostics-reproducer-20260915` в корне проекта.

Отчёт теперь читает только булевы настройки автоматики, количество подписок, версию ядра и проекцию identity трёх служб. Чужие/повреждённые identity сохраняются. URL, имена, credentials, command line, токены и исходные ошибки не возвращаются. Service classifier изолирован в subshell и не меняет owner context координатора.

Настройки ограничены 32 KiB, запись подписки — 64 KiB. Каталог свыше 32 записей отклоняется до открытия записей, с `SUBSCRIPTION_SETTINGS_UNAVAILABLE` и `subscriptionRecordsRead:0`. Это исправляет timeout диагностического GET на большом каталоге, обнаруженный первым Linux прогоном. Неполные данные обозначаются явно.

Проверки: 28 Linux PASS (диагностика 9, публичная проекция 7, CGI 12), 145,62 с; 6 физических ARM64 PASS. Первый physical fixture не создал обязательный пустой каталог operations; вызов завершился UNSAFE_STATE до проверок. Архив сохранён, отсутствие работ подтверждено, fixture удалён; исправленный повтор PASS. Это ошибка подготовки теста, production не менялся.

Ограничения: фактическая VPN continuity, KeeneticOS и identity Xray/updater пока не выводятся. `complete:false` сохраняется. Эти проверки не подтверждают полную установку приложения или готовность релиза.
