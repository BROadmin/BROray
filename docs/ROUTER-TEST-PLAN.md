# Физический стенд BROray 3.1.1

**Сейчас не запускать.** Роутер занят другим процессом. В локальном наборе отсутствуют транспорт SSH, целевой IP и автоустановщик.

## Порядок подключения

1. Дождаться явного сообщения пользователя об освобождении роутера. Зафиксировать, что чужая работа закончена.
2. Выполнить `tests/router-preflight.sh` чтением. Сохранить JSON, его SHA и время. Сверить точную версию/кандидат, архитектуру и доступность `/proc` identity. Не выводить сырые конфиги и подписки.
3. Проверить native ARM64 guard отдельно в специально созданном временном каталоге стенда. Запуск `--version` не доказывает fcntl/fsync; нужны локальные конкурирующие workers на том же filesystem, где находится `/opt/var/lib/broray`.
4. Закрыть begin/ack, child-registration, legacy migration и безопасный delivery. Сформировать конкретный candidate manifest и откат. Не пытаться «проверить» установку удалением lock через SSH.
5. Проверить нормальный цикл, затем fault injection, затем concurrency и soak. При первой обязательной ошибке остановить переход к следующему этапу и исправить дефект.

## Наблюдения для каждого сценария

Начальный/конечный public report, точный SHA кандидата и scripts, owner generation, классификация fence, terminal state, количество серверов/подписок/маршрутов, хэши настроек в приватной части стенда, Xray PID+birth, uptime, результаты непрерывного тестового потока и новых VPN-запросов. Не помещать сами credentials/config в публикуемый отчёт.

| Сценарий | Проверка приёмки |
| --- | --- |
| Нормальный update/check/auto-switch | terminal state, ресурс освобождён, следующий запрос выполняется |
| Crash до публикации fence | никакой частично опубликованной блокировки; abandoned starting распознан |
| Crash после publication до begin-response / ack-response | повторная попытка того же producer не зависает на собственном PID |
| Parent crash при живом worker | fence сохраняется до подтверждённого окончания всех children |
| Живой владелец со старым heartbeat | recovery не удаляет fence и не сигналит процессу |
| PID reuse, unreadable proc, malformed state | чужой процесс сохранён; неоднозначность объяснена в UI |
| Cooperative cancel при загрузке/парсинге | ограниченный срок до terminal cancelled, нет частичного merge |
| TERM и KILL управляемого helper | только доказанный child/session, не главный Xray; lifetime/PID reuse test |
| Cancel при protected commit/activation/updater | 409/защищённый этап; не выполнять общий kill |
| Непрерывность VPN | существующее соединение и новые запросы продолжают работать при cancel/recovery |
| Перезагрузка/отключение питания | после старта нет stale permanent fence; защищённая транзакция восстановлена своим механизмом |
| Старый system-lock 3.1.0 | supported recovery/install через UI, без ручного rm, обязательного reboot или reinstall Entware |
| Все автоматические функции и ручные запросы | нет двойного владельца, starvation и постоянной блокировки |
| Updater/reinstall | отказ при реальном конфликте; после подтверждённого recovery снова доступен |
| Диск заполнен/readonly/сбой журнала | API сообщает неполноту; cleanup безопасен; bounded storage |
| Секреты, auth, CSRF, traversal | ни одного canary в UI/log/download/error; отказ в неавторизованных мутациях |

## Длительный прогон

Минимум 24 часа реального combined automation плюс ускоренные циклы с искусственными задержками и контролируемыми ошибками. Для исходного дефекта «через несколько дней» нужен последующий прогон не менее 72 часов; ускоренный тест не заменяет длительность. Никакая автоматизация/мониторинг в текущей задаче не создаётся. Настройка будет отдельным действием, когда стенд станет доступен.

## Критерий остановки

При изменении Xray вне согласованной activation, пропаже VPN, повреждении данных, удалении живого/неоднозначного fence или потере recovery зафиксировать FIRST ERROR и прекратить следующие мутации. Не применять общий killall, reboot или ручной rm lock как тестовый cleanup. Откат проводить только предусмотренным путём конкретного кандидата.

Release gate: все обязательные проверки A–R исходного задания + UI 1440/1024/390/360 и обе темы + уникальные version/build/candidate + воспроизводимый архив и SHA + доказанный путь доставки на заблокированную базу. До этого комплект не объявляется релизом.
