# BROray 2.2.6 — release candidate

## Статус

BROray 2.2.6 подготовлен как **неизменяемый release candidate**, а не как уже опубликованный стабильный релиз. Текущий публичный стабильный канал остаётся на BROray/OPKG 2.2.4.

Публичное продвижение 2.2.6 разрешено только после физического теста тех же байтов через WebUI и итогового отчёта `PASS`.

## Причины выпуска

BROray 2.2.5 был отозван после реального теста на роутере с версией `2.2.0-2`:

1. updater передавал резервную копию полного `/opt` с путями `broray/...`, а пакетный `preinst` принимал только rootless-пути `bin/`, `lib/`, `web-new/`, `config/`;
2. функция записи состояния служб не имела явного успешного возврата и могла завершиться кодом остановленной последней службы;
3. пользователю показывалась общая ошибка OPKG без полезного хвоста `preinst`/`postinst`;
4. серверная публикация первоначально выдала `.sh` с правами `0700`, из-за чего Nginx отвечал `403`.

## Исправления 2.2.6

- два явных допустимых формата backup;
- `return 0` после успешного учёта служб;
- `BRORAY_OPKG_CLEANUP_DONE=1` при передаче уже проверенной копии;
- полный журнал OPKG до отката;
- staging-публикация с внешней HTTP/SHA-проверкой;
- права публичных статических файлов `0644`;
- правила релиза 1.3 и запрет пересборки после field test.

## Candidate builder r2

Первая попытка builder r1 была безопасно остановлена независимой проверкой распаковки: каталоги `check/control` и `check/data` не создавались до извлечения внутренних архивов. Публичный канал не изменялся, а release candidate не был создан.

Builder r2:

- создаёт оба каталога до независимой распаковки;
- исключает бинарный Xray из чтения shebang через command substitution;
- использует отдельный candidate-id `r2`;
- прошёл `bash -n`, изолированный тест вложенной распаковки и тест отсутствия NUL-предупреждений.

Файл серверного builder:

```text
BROray-2.2.6-release-candidate-builder-r2.sh
```

SHA-256:

```text
759386247553adc0d1ee64e43bc53c8606c5aa88a5d0c6a72a9674e09660c0c3
```

## Порядок выпуска

1. На сервере собрать candidate r2 из точных файлов отозванного 2.2.5 в карантине.
2. Сверить внутренний `SHA256SUMS` и внешний SHA архива кандидата.
3. Опубликовать candidate только в `/releases/staging/broray/2.2.6-r2/`.
4. Подготовить тестовый роутер к staging и запустить установку исключительно из WebUI.
5. Выполнить матрицу из [`FIELD-TEST-2.2.6.md`](FIELD-TEST-2.2.6.md).
6. После `PASS` продвинуть точные байты без пересборки; затем обновить документацию, GitHub tag и release notes.

## Что не считается выпуском

- лабораторная распаковка IPK;
- успешный `bash -n`/`ash -n`;
- локальная симуляция публикации;
- ручной `opkg install` вместо WebUI;
- установка пересобранного после field test пакета.
