# Подготовка полной установки 3.1.1

Исторический универсальный установщик и встроенный bootstrap 3.1.0 не запускались. IPK извлечён без выполнения hooks из точного `publication-3.1.0-r09c02`; его SHA-256 `630515677ad609a94ff85f2af0649fe23fe18537591f058a8f4a5e4bac2d6f92`. Данные пакета пусты: установка выполняется postinst, который загружает приложение, updater platform и Xray. Локальная распаковка и hashes находятся в `.local/bootstrap-audit` в корне проекта.

## Проверенная последовательность

1. Preinst проверяет отсутствие BROray, архитектуру, компоненты proxy/opkg/ndns, доступность API, место и 4096 временных inode. Постоянные настройки не меняет.
2. Postinst проверяет размер и SHA всех четырёх входов; архивы, список файлов, JSON, shell syntax, Xray version и место. Повторяет clean boundary и определение LAN перед первой постоянной записью.
3. Создаёт принадлежащие установке корни приложения/состояния, общий Xray, updater-v5, первый current slot, seed только для отсутствующих файлов, совместимые ссылки и init links.
4. Встроенный helper вызывает шесть функций: runtime directories, permissions, local address, lighttpd, initial Xray, command links. Остальное тело старого package setup не выполняется.
5. Запускает updater, WebUI и Xray с первоначальным blackhole outbound; создаёт принадлежащий BROray ProxyN и HTTP proxy; проверяет HTTP 200, отказ неавторизованному session CGI и контрольные суммы.

## Что требуется для кандидата 3.1.1

- Пересобрать bootstrap из согласованных candidate metadata и hashes; исходный postinst жёстко привязан к 3.1.0-r09c02 и его staging URL.
- Проверить package control: поля Initial-Xray в исходном control содержат старую 26.7.28, тогда как фактический postinst устанавливает 26.9.9. Новый пакет должен описывать фактические входы.
- Не считать старый `ROLLBACK=PASS` достаточной проверкой: rollback содержит подавленные ошибки удаления/остановки. Проверять окончательное состояние и сохранять незавершённый rollback.
- Перед полной установкой закрыть обязательную регрессию текущего этапа и подготовить отдельный конкретный test candidate с известными SHA. Состав архивного слота уже проверен штатным validator на физическом роутере.
- Проверять неизменность существующих сетевых объектов и доступа Keenetic; новые объекты BROray должны иметь доказанную принадлежность. Не использовать общую очистку конфигурации или удаление lock через SSH как восстановление.

Полный вызов зависимостей interface repair, web publish, S24 и updater требует отдельной проверки. Этот документ фиксирует анализ bootstrap, а не разрешает исполнение непрочитанных вложенных скриптов и не подтверждает установку приложения.
