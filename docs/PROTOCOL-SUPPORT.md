# Протоколы, транспорты и импорт конфигураций

Документ выпуска **3.5.6**, 12 ноября 2026 года. Он продолжает опубликованные 3.5.3 и 3.5.4. Схемы ядра сверены с официальным Xray **26.11.9**; исторические результаты ядра — в [ACCEPTANCE-3.5.3](ACCEPTANCE-3.5.3.md). Новые изменения импорта приняты в указанном объёме: [ACCEPTANCE-3.5.5](ACCEPTANCE-3.5.5.md).

BROray продолжает существующий проект. Наличие протокола в Xray, его импорт в BROray и проверка конкретного провайдера — разные свойства. Поддерживаемый контракт: [матрица параметров](XRAY-26.11.9-PARAMETERS.md). Полный учёт деклараций, включая неподдержанные поля и серверные исключения: [реестр схем 26.11.9](XRAY-26.11.9-SCHEMA.md). Строка реестра сама по себе не означает работающую поддержку.

## Протоколы и форматы

| Протокол | Ввод в BROray | Выполнение и ограничения |
|---|---|---|
| VLESS | `vless://`, Xray JSON в подписке | Поддержанные транспорты и поля; XDRIVE дополнительно принимает ручной JSON |
| VMess | современные/legacy `vmess://`, Xray JSON в подписке | RAW/WS/gRPC/HTTPUpgrade/XHTTP/mKCP в разрешённых сочетаниях |
| Trojan | `trojan://`, Xray JSON в подписке | TLS либо REALITY на RAW/gRPC/XHTTP; непустые VLESS-поля flow/encryption отклоняются, JSON flow="" — нейтральное значение |
| Shadowsocks | `ss://`, Xray JSON в подписке | Поддержанные методы, включая 2022; SIP003-плагины не поддерживаются |
| Hysteria2 | `hy2://`, `hysteria2://`, JSON `hysteria` version 2 в подписке | TCP/UDP; idle timeout 0 или 2–600 |
| SOCKS5 | `socks://`, `socks5://`, Xray JSON в подписке | TCP/UDP; один сервер/пользователь |
| HTTP/HTTPS proxy | `http://`, `https://`, Xray JSON в подписке | Только TCP |
| WireGuard | один клиентский INI, Xray JSON в подписке | userspace Xray, без kernel TUN; начиная с 3.5.3 работа на MIPS/MIPS LE не подтверждена: см. ограничение ниже |
| MASQUE | родной JSON вручную/из файла/из подписки | Xray ≥26.11.9; H2/H3, remote DNS, auth, готовые WARP-параметры |
| VLESS/XDRIVE | родной JSON вручную/из файла/из подписки | Xray ≥26.11.9; Encryption и Mux обязательны; local/Google Drive/S3/template |
| AmneziaWG | поддержанный `vpn://` | Только хранение; подключение отложено |
| TUIC, MTProto Proxy, Hysteria1, SSR, Snell | Нет | Не включены в поддерживаемую клиентскую модель |
| OpenVPN, IKEv2, L2TP, PPTP | Нет | Компоненты Keenetic не являются backend BROray |

Транспорты RAW/TCP, WS, gRPC, HTTPUpgrade, XHTTP и mKCP сохраняют поддержку 3.5.2. Самостоятельные старые HTTP/H2/H3/QUIC не принимаются; H2/H3 внутри XHTTP и MASQUE — отдельные механизмы. REALITY разрешена только в поддержанных сочетаниях, не с произвольным транспортом.

## Новые JSON-профили

В «Серверы → Добавить сервер» вставьте один родной JSON outbound XDRIVE/MASQUE целиком либо выберите UTF-8 файл. Затем нажмите «Проверить конфигурацию» и сохраните после просмотра результата. Ручной запрос ограничен 64 КБ вместе с JSON-оформлением; подпись размера файла не заменяет проверку размера запроса. Подписки сохраняют прежний лимит 2 МиБ.

JSON преобразуется непосредственно в приватную Record, без придуманной URI-схемы. При извлечении из полного профиля чужие inbound/routing/DNS/API не запускаются; предупреждение перечисляет непереносимые настройки. Неизвестные или неприменимые существенные поля дают ошибку, дубли ключей JSON отвергаются. Повреждённый/частичный ответ подписки не доказывает удаления прежних узлов.

Для подписки родной JSON должен содержать `outbounds`: отдельный bare outbound принимается ручным импортом XDRIVE/MASQUE, но пока не является форматом подписки. Обычные VLESS/VMess/Trojan и другие JSON-outbound импортируются через подписку с `outbounds`; ручная вставка их JSON пока не поддерживается. Массив полных профилей допускается в подписке, массив отдельных outbound — нет. Эти ограничения перечислены и проверяются отдельно; наличие парсера протокола не означает поддержку любой оболочки файла.

Если ядро старое, профиль можно сохранить, но подключение, проверка качества и автовыбор заблокированы с требованием обновить Xray. Понижение ядра при активном профиле, которому требуется 26.11.9, тоже блокируется. Обновление BROray само не меняет установленное ядро.

XDRIVE требует согласованной версии Xray на клиенте и сервере. При импорте JSON без блока `mux` BROray добавляет обязательный `mux.enabled=true` и предупреждает о применении локальной политики мультиплексирования. Это нормализация неполного экспорта; сам Xray отсутствующий блок не принимает. Явно переданный некорректный `mux` отклоняется; для других транспортов этот блок не добавляется. REALITY/flow не сочетаются с этой моделью. local разрешён только в собственном отмеченном каталоге `/opt/broray/run/xdrive-local`; чужие каталоги и symlink не принимаются. Время установления и задержка прогретого туннеля показаны отдельно: формальный адрес не используется как ICMP-оценка качества. Фоновый монитор читает свежую HTTPS-проверку текущего туннеля, не создавая дополнительные облачные подключения.

Ключи, пароли и заголовки не показываются в карточках и диагностике. Необработанные access/error логи Xray для XDRIVE/MASQUE отключены: ошибки облачного API могут включать секреты. Это относится и к временной проверке качества. Резервная копия содержит реквизиты подключения и требует сохранения предусмотренной защиты.

Local/S3/template и MASQUE H2/H3 проверялись с настоящим ядром в изолированной VM. S3/template использовали собственный тестовый API. В 3.5.5 Google Drive проверен на KN-1811 через изолированный Xray: файлы 1 и 8 МиБ получены полностью, но задержка высокая. Путь LAN/ProxyN, длительная нагрузка и реальный публичный WARP не проверены. Валидный синтетический WARP JSON не считается успешным подключением к WARP.

## Существующие расширения

**Сохраняющееся ограничение — WireGuard на MIPS/MIPS LE.** При обычном запуске клиента официальный Xray 26.11.9 завершался с ошибкой в эмуляции обеих архитектур. Контроль с предыдущим ядром и другим окружением не снял проблему; точная причина не установлена. На ARM64/ARMv7 локальные проверки проходят. На настоящем MIPS-роутере этот отказ не подтверждён. Импорт и сохранение профиля остаются доступны, но работоспособность WireGuard на MIPS в этом выпуске не заявляется. Владелец согласовал продолжение подготовки с этим ограничением; оно не означает успешную полную приёмку архитектуры.

WireGuard сохраняет PrivateKey, Address, DNS, MTU, Reserved и до 32 Peer с PublicKey, PresharedKey, Endpoint, AllowedIPs, PersistentKeepalive. INI вводится целиком в поле импорта серверов. В JSON используются родные имена Xray (`secretKey`, `remoteDNS`, `keepAlive` и др.). Адрес и порт в карточке берутся из первого пира. Требуются явный клиентский адрес, ключ и endpoint каждого пира. Команды PostUp/PostDown, параметры AWG, неизвестные директивы и `noKernelTun: false` отклоняются. Произвольный WireGuard JSON не запускается как полный профиль.

Параметры транспортов в Xray JSON принимаются в родных блоках. В ссылках добавлено percent-encoded JSON-поле `streamOptions`:

```json
{"wsSettings":{"headers":{"X-Client":"example"},"heartbeatPeriod":30},"sockopt":{"tcpFastOpen":false,"tcpKeepAliveIdle":0,"domainStrategy":"UseIPv4"}}
```

- WS: дополнительные `headers` и `heartbeatPeriod`.
- HTTPUpgrade: дополнительные `headers`.
- gRPC: `idle_timeout`, `health_check_timeout`, `permit_without_stream`, `initial_windows_size`, `user_agent`.
- sockopt: `tcpFastOpen`, `tcpKeepAliveIdle`, `tcpKeepAliveInterval`, `domainStrategy`; остальные поля отклоняются.
- Host задаётся основным полем `host`. В Xray JSON заголовок Host нормализуется в это поле; конфликт с явным host отклоняется. В `streamOptions.headers` Host запрещён.
- Сохраняются `false` и `0`. CR/LF, неверные имена HTTP-заголовков, неоднозначные поля и неизвестные настройки отклоняются. Настройки с потенциальными секретами скрыты из публичного details API.
- `x_padding_bytes` нормализуется в XHTTP `extra.xPaddingBytes`; конфликт значений отклоняется. Непустой `extra` вне XHTTP отклоняется, включая старый бессмысленный вариант `extra=0`.
- Для новых импортов неизвестные query-поля и поля старого VMess JSON дают явную ошибку. Служебный `support-x25519mlkem768` сопровождается предупреждением; его значение не исполняется. При импорте Xray JSON предупреждение перечисляет непереносимые настройки профиля и служебные поля.

Это не обещание произвольных сочетаний всех возможностей Xray. Сохраняются прежние ограничения TLS/REALITY/FinalMask и XHTTP extra. В частности, HTTP proxy-specific headers, произвольные socket options, SIP003-плагины, TUIC и MTProto не поддерживаются. JSON новых XDRIVE/MASQUE можно импортировать вручную или через подписку; прежние JSON-протоколы импортируются через подписку.

Исторический отчёт расширения 3.5.2: [PROTOCOL-IMPORT-REPORT](PROTOCOL-IMPORT-REPORT.md). Результаты 3.5.3 сохранены отдельно; без изменений ядра эти проверки не повторяются для 3.5.5.


## AWG: границы рабочей реализации

Принимается один `amnezia-awg` / `amnezia-awg2` контейнер с `awg.last_config` (JSON-строка), содержащим готовый клиентский INI в `config`. Поддержаны Base64URL/обычный Base64 и Qt qCompress. Также принимается `vpn://` с обычным клиентским INI в Base64: нужны секции Interface/Peer и узнаваемые параметры AWG (например, Jc, H1 или I1). Чистый WireGuard в такой ссылке не объявляется AWG. Сохраняются исходная ссылка, контейнер или отметка формата INI, параметры Interface/Peer, неизвестные расширения. Структура и ключи проверяются; семантика всех AWG-параметров и совместимость с будущим backend не заявляются. Лимиты декодирования и хранения сохранены.

Лимиты парсера: ссылка 64 KiB; распакованный JSON 256 KiB; сохраняемая модель 512 KiB; глубина JSON 64; до 32 пиров и 128 различных полей в секции; строка INI до 16 KiB. Ручная WebUI-форма дополнительно сохраняет прежний предел 16 KiB на одну ссылку, HTTP API — 64 KiB на всё тело запроса. Повторные JSON-поля и неоднозначные контейнеры отклоняются. Не поддержаны импорт голого INI, административные контейнеры без готового клиентского INI, другие протоколы внутри `vpn://` и произвольный многоконтейнерный экспорт.

Валидный AWG принимается в подписку с предупреждением. Удаление/обновление проходят штатную синхронизацию. Повреждённый узел включает существующую защиту неполной подписки. Подключение, проверка качества и выбор AWG в автоматике запрещены; секретные данные не выдаются в summary/details. Нового подключения на роутере эта функция не создаёт.


## Синхронизация в 3.5.2

SNI/ShortID могут меняться у одного узла. Внутри одной подписки сохраняется ID при однозначной ротации, накопленные совпадающие по прочим параметрам копии объединяются. Ручные источники и другие подписки остаются независимыми. Исчезновение активного узла по полному ответу удаляет его из каталога и прекращает старое подключение; включённый автовыбор ищет замену по своим настройкам. Неразобранный/повреждённый ответ не доказывает удаления узлов.

## Поправки импорта 3.5.5

Пустая строка диапазона XMUX, например `maxConcurrency: ""`, означает 0..0, как в Xray. Это одинаково для URI extra и JSON. Недопустимые типы, отрицательные и слишком большие значения по-прежнему отклоняются.

Допустимый `level` из JSON нормализуется к локальной политике BROray с предупреждением. VLESS, VMess, HTTP, SOCKS и WireGuard допускают целое 0..4294967295; Trojan и Shadowsocks — 0..255, согласно схемам Xray26.11.9. Native XDRIVE использует границы VLESS. Реквизиты сервера и транспорта сохраняются; полный блок `policy`, DNS и маршрутизация чужого профиля не применяются.

При полном отказе разбора сохраняются фактические счётчики и причины отказа узлов. Существующий каталог этой подписки остаётся на месте. Ошибка загрузки без полученного содержимого не получает вымышленных результатов разбора.

### Clash/Mihomo по ссылке подписки

По основной ссылке BROray также запрашивает HTML-представление и ищет явно указанные JSON/Clash-выгрузки того же источника: ссылки с названием/MIME формата и статические поля `subJsonUrl` / `subClashUrl` в данных страницы 3x-ui. JavaScript не исполняется, пути выгрузок не подбираются, вложенные providers не обходятся. JSON-массив ссылок на серверы также принимается.

Все найденные форматы подготавливаются до изменения каталога одной подписки. Полные совпадения настроек объединяются по ключу конфигурации; отличающиеся настройки сохраняются. Счётчики «получено» и «разобрано» учитывают записи во всех выгрузках, «принято» — уникальные конфигурации. Разница этих счётчиков сама по себе не означает отказ: точные совпадения не считаются ошибкой. Если дополнительная выгрузка не загрузилась или содержит отказанные узлы, прежний каталог сохраняется. Ранее обнаруженные форматы запоминаются, поэтому временное исчезновение HTML-страницы или ссылок на выгрузки не удаляет их серверы.

Для автоматического поиска действуют пределы: HTML до 512 KiB, совокупный объём ответов до 4 MiB, до 500 входных записей суммарно и не более одной JSON- и одной Clash-выгрузки. Каждое соединение проверяет публичность адреса и TLS; переход найденной выгрузки на другой источник запрещён. При переходе основной ссылки на другой источник идентификатор устройства не пересылается. Ошибки содержат обозначение формата, без приватных адресов выгрузок.

Противоречивые ссылки отклоняются: например, разные адреса для одного формата или один адрес, одновременно объявленный как JSON и Clash. В таком случае можно указать однозначную прямую ссылку на нужную выгрузку.

На странице «Серверы» одна карточка может представлять несколько источников одного подключения. Внутри карточки выбирается исходная запись; проверка, подключение, подробности и удаление относятся к выбранной записи. Сам выбор источника VPN не переключает. Записи и настройки каждой подписки сохраняются отдельно, поэтому отключение или удаление одного источника не удаляет записи других. Разные учётные данные или значимые параметры транспорта не объединяются только по одинаковому названию.

Принимается один YAML-документ с верхним списком `proxies`, в том числе полный конфиг Clash или файл proxy-provider с таким списком. JSON-запись того же документа также допустима. Это импорт серверов со страницы «Подписки»; ручной файловый импорт на странице «Серверы» не заявляет поддержку YAML.

| Вариант | Объём импорта |
|---|---|
| VLESS, VMess, Trojan | Реквизиты сервера, поддержанные TLS/REALITY и транспорты TCP, WS, gRPC, XHTTP, HTTPUpgrade |
| Shadowsocks | Методы, уже поддержанные Xray и валидатором BROray; без SIP003-плагинов |
| HTTP, SOCKS5 | Адрес, порт, учётные данные, поддержанный TLS; ограничения UDP для HTTP сохраняются |
| Hysteria2 | Базовый профиль с паролем и TLS; дополнительные неподдержанные опции отклоняются |
| WireGuard | Однопировая форма; клиентский адрес, ключи, MTU и поддержанные поля. Не все расширения Mihomo переносимы |
| WireGuard с `amnezia-wg-option` | Сохраняется как AmneziaWG, вместе с исходными параметрами. Подключение через Xray не выполняется |

Для XHTTP переносятся `path`, `host`, `mode`, padding, булевый `no-grpc-header` → `noGRPCHeader` и поддержанные параметры `reuse-settings` в XMUX. Служебный `support-x25519mlkem768` получает предупреждение о различии клиентов. Стандартный вариант HTTPUpgrade задаётся через `network: ws` и `ws-opts.v2ray-http-upgrade: true`; неподдержанные early-data/fast-open параметры не теряются молча.

DNS, rules, proxy-groups, providers и локальная политика UDP из Clash не применяются. Удалённые providers не скачиваются. Группа `select` не является дополнительным сервером. Неизвестные протоколы и параметры отклоняются по узлам с указанием причины, без вывода значений ключей и паролей. Это не обещание поддержки любого конфигурационного файла Mihomo: например, TUIC, Snell, MTProto, плагины, цепочки `dialer-proxy` и неподдержанные транспортные расширения не исполняются.

Вход ограничен размером 2 MiB и 500 серверами. До декодирования действует консервативный предел 20 тысяч разделителей и переводов строк, включая символы внутри строковых значений. После декодирования допускаются глубина до 32 и до 20 тысяч посещений элементов, включая разворачивание aliases. Повторные ключи, циклические ссылки, дополнительные документы и неизвестные теги отклоняются. Ограниченные обычные aliases допустимы; YAML merge `<<` не поддерживается. Эти ограничения защищают память роутера и не заменяют проверку каждого сервера.

## Поправка импорта 3.5.6

Корректный серверный блок Hysteria2 masquerade проходит проверку известной структуры и исключается из клиентского подключения с предупреждением. Неизвестные поля и неверные типы не игнорируются. Авторизация, TLS/ECH и тайм-аут сохраняются. [Приёмка 3.5.6](ACCEPTANCE-3.5.6.md).
