# BROray 2.2.5

## Статус

Опубликован 31 июля 2026 года. Публичный OPKG-feed и документация прошли атомарную серверную проверку со статусом `success`, кодом `0`. Обновление с реально установленной версии `2.1.1-2` успешно завершено через WebUI на реальном Keenetic.

Версия 2.2.4 отозвана после обнаружения нарушения правил резервного копирования и preflight свободного места.

## Исправления

- перед обновлением удаляются все старые резервные копии BROray, старые релизные файлы, управляемые временные данные и OPKG-кэш;
- после очистки заново проверяется свободное место в `/opt` и `/tmp`;
- создаётся ровно одна актуальная резервная копия и только в `/tmp`;
- `preinst` больше не создаёт копию в `/opt/broray/backups`;
- `package-setup` больше не создаёт отдельную копию `lighttpd.conf` во время обновления;
- реальное требование к месту хранится в `X-BROray-Required-Opt-KB: 42000` и проверяется до распаковки;
- `Installed-Size` содержит только совместимый резерв для старого OPKG: это позволяет войти в `preinst`, перенести ошибочно созданную старым updater копию из `/opt` в `/tmp`, очистить мусор и затем проверить реальные 42000 КБ;
- WebUI показывает фактические доступные и требуемые КБ;
- при неудачном откате аварийный `/tmp`-каталог сохраняется, а не удаляется;
- версия WebUI: `WebUI-2.2.0-r3`;
- исправленный updater и список правил включены в пакет и документацию;
- для updater 2.1.1-2 добавлен `preinst`-мост: предварительная копия из `/opt/broray/backup` переносится в `/tmp`, старая история очищается, после чего создаётся новая актуальная копия уже по принятому порядку.

## Обязательная полевая проверка

```text
BROray → Проверить обновление → Установить обновление
```

Проверка должна начинаться с реально установленной предыдущей версии. Ручная установка IPK не засчитывается как релизный тест.

## Полевое подтверждение

Проверенный пользовательский путь:

```text
BROray 2.1.1-2
→ Проверить обновление
→ доступна 2.2.5
→ Установить обновление
→ установка завершена
```

До успешной попытки были выявлены и исправлены два дефекта совместимости старого updater:

1. `SHA256sum` не читалась из сжатого локального списка OPKG `src/gz`.
2. В скопированном фоновом worker отсутствовало значение `BRORAY_OPKG_LISTS_DIR`, из-за чего эталонная SHA-256 становилась пустой.

После ремонта механизм на роутере показал одинаковые значения:

```text
Ожидаемая SHA-256:
8a2255e2c181a5f88438673c186da4f89870cb54bc01e656d57671d46cae9adc

Фактическая SHA-256:
8a2255e2c181a5f88438673c186da4f89870cb54bc01e656d57671d46cae9adc
```
