# Статус истории и ранняя отмена

На установленном r04c01 первый stop-background при удержании kernel guard на четыре секунды принят: HTTP 202 через 4,64 с. Однако refresh вернул 503 OPERATION_UNRESOLVED, а durable операция завершилась aborted/CANCELLED. HTTP-источник ещё не получил загрузку: сценарий воспроизвёл раннюю отмену. Точная внутренняя точка возврата 75 не трассировалась, поэтому конкретный вызов не объявляется доказанной причиной. Ошибка и все ответы сохранены в `full-subscription-r04-20260916`.

## Подтверждённые причины задержки и исправление

Status при 19 завершённых операциях занимал 3,06–3,30 с на установленном приложении. Под общим guard для каждой terminal записи выполнялись полная загрузка owner и повторная проверка процесса. Отдельный сравнительный physical prefix прогон с 19 владельцами, ещё живущими в тестовом процессе, показал 5,60 с старого controller против 0,85 с нового.

Теперь проверенная terminal запись читается как история, с ownerStatus FINISHED и ownerReason operation_finished. Это не подтверждение отсутствия процесса и не разрешение удалять его состояние. Активные записи и фактическая глобальная блокировка проходят прежнюю полную проверку владельца. Recovery, prune, kill и admission не используют этот быстрый путь. Повреждённое terminal состояние и неоднозначный global fence не превращаются в успешный idle; чтение не пишет файлы.

Если service вернул 75 до неподтверждённой стадии и уже есть запрос отмены, API подписок сначала пытается подтвердить owner и terminal aborted через job_finish. Только после успешного завершения возвращается OPERATION_CANCELLED/409. При BRORAY_JOB_UNRESOLVED=true или неудаче проверки остаются 503 и fence. Это не маскирует непроверенные helper или publication failures.

## Физические проверки

Четыре PASS в `physical-status-history-20260916`: время чтения, подтверждённая ранняя отмена, сохранение fence при unresolved, явное восстановление после выхода тестового owner. Namespace архивирован и удалён; установленный r04 не менялся.

Полное обновление r03→r04 через WebUI (`update-20260915230710-17001`) успешно, tree hashes, network config, access и protected files сохранены. Неудачный HTTP тест завершён, тестовая подписка удалена, Xray identity и файлы восстановлены. Следующий полный тест обязан дождаться фактического обращения к HTTP fixture перед отменой.

Linux regression: 102 PASS за 747,61 с (57 coordinator, 7 public projection, 12 HTTP, 12 subscription jobs, 9 diagnostics, 5 contention). Source checks PASS. Результаты закреплены в `status-responsiveness-001`. Stable не публиковался; VPN-трафик и общая готовность релиза этим этапом не подтверждаются. ROOT_CAUSE_NOT_PROVEN исходного инцидента сохраняется.
