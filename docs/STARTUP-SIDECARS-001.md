# S24: остановка вспомогательных служб

До правок на физическом Keenetic воспроизведены два дефекта: home-snapshot stop и interface-reconcile stop удаляли PID-файл с неподтверждённым владельцем. Сценарий использовал только приватные каталоги и заведомо отсутствующий PID; ни одна установленная служба не останавливалась. Исходные функции, hashes и результаты сохранены в `s24-sidecars-baseline-20260916`.

Обе службы подключены к существующему service lifecycle: полный owner, generation-bound stop, постоянный kernel lifetime lease. S24 проверяет остановку sidecars до вызова rc.func, поэтому неоднозначность не приводит к остановке Xray. Старые неподтверждённые PID-файлы сохраняются. Занятая служба сообщает stopping/pending до окончания текущего вызова; принудительных сигналов по PID-файлу нет.

Home-snapshot проверяет stop между модулями и во время ожидания. При восстановлении monitor дочерний запуск не наследует singleton lease домашней панели. Interface-reconcile вынесен из встроенной строки start-stop-daemon в отдельную конечную службу. Он принимает protected operation перед сетевыми изменениями, учитывает общую паузу и сохраняет fence при неподтверждённом результате изменения. Domain recovery этого fence остаётся отдельным незавершённым release gate.

Проверки: 32 Linux PASS (13 sidecars, 11 service lifecycle, 8 monitor), 378,8 с; отдельно 3 Linux PASS фактического входа S24 с безопасным rc.func sentinel. Единственная более поздняя правка S24 — передача ошибки запуска reconcile вместо её подавления. В физическом приватном namespace пройдено 7 ARM64 сценариев, архив получен до очистки; обе службы подтверждённо остановлены, lifetime guards свободны. Изолированная намеренно неуспешная protected operation сохранена внутри архива.

На установленном полном приложении всё ещё работает старый r01c01. Новые байты ещё не установлены. Переход со старого PID lifecycle требует отдельно проверенного quiescence; выполнение старой S24 stop не считается безопасной миграцией. VPN, full update/rollback, reboot и endurance этим этапом не подтверждаются.

## Коррекция тестового bootstrap

В нашем локальном r01c01 test descriptor были потеряны appSlot.layout и актуальный bundle.sizeBytes. Это ошибка тестовой упаковки, не runtime updater. Замороженные артефакты не изменялись. Под coordinator protected admission исправлена только `.source` установленного slot metadata: возвращён layout, размер 2064588, удалено ошибочное поле bytes. SHA до `c726ef5915bb8371095dd20aedd9611d6becd2d164242cc2ab39d7aef6203a34`, после `8066f1d0894cddb91d935a0faa748574dcc78f8a9bafbc6742b7f4e35f1f06ad`. Все runtime checksums перед исправлением подтверждены.

## Доставка через Keenetic

В аутентифицированном Web CLI Keenetic 5.1 выполнена `exec sh -c "printf BRORAY311_WEBCLI_PROBE"`; наблюдались точный маркер и process terminated. Это подтверждает доставку Entware-команды. Полное signed recovery старой заблокированной 3.1.0 ещё не выполнялось; первоначальное исследование сохранено как история.
