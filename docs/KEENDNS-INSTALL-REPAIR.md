# После установки BROray открывается только локально

В 3.5.0–3.5.5 установщик не создаёт внешний адрес автоматически. Если основная панель Keenetic доступна по KeenDNS, переустановка BROray не нужна.

1. Оставьте основную панель роутера открытой. Откройте её веб-терминал. Если приглашение выглядит как `(config)>`, выполните `exec sh`: следующие команды предназначены для shell Entware.
2. Проверьте запуск BROray:

```sh
/opt/bin/broray ctl ping
```

3. Если получен `success:true`, включите адрес:

```sh
/opt/bin/broray ctl post /api/keenetic/web-access-enable.cgi '{}'
```

4. После успешного ответа проверьте результат:

```sh
/opt/bin/broray ctl get /api/keenetic/web-access-status.cgi
```

В `data.address` будет готовый адрес `https://broray.…/`. Успешный результат: `data.state` равен `enabled`, а `data.enabled` и `data.consistent` равны `true`. Откройте именно полученный адрес. Для создания адреса подключение к VPN не требуется. Перезагрузка не нужна.

Если команда вернула ошибку, сохраните её код и остановитесь:

- `KEENDNS_ADDRESS_UNAVAILABLE`: проверьте регистрацию имени KeenDNS в основной панели.
- `WEB_ACCESS_OWNERSHIP_CONFLICT`, `WEB_PUBLISH_RECEIPT_INVALID` или `WEB_PUBLISH_RECEIPT_LIVE_MISMATCH`: запись broray и сведения о её владельце не согласованы. Не удаляйте запись или файлы вручную; нужна проверка конфигурации.
- Код с `RECOVERY_REQUIRED`: используйте диагностику предыдущей операции, не повторяйте включение бесконечно.
- `OPERATION_BUSY`: дождитесь завершения текущей операции и повторите команду один раз.
- `is the daemon running?`: сначала проверьте службу BROray; команда публикации требует запущенного приложения.

`enabled` подтверждает настройку адреса на роутере. Если внешний сайт всё ещё не открывается, отдельно проверьте доступность основной панели KeenDNS и локального BROray: состояние облачного доступа и доступность приложения — разные проверки.
