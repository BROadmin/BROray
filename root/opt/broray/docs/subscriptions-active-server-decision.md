# Подписки: правило активного сервера

## Проверенный существующий код

До этого модуля импорт подписки формировал идентификатор по позиции узла:
`subscription-<subscriptionId>-<nodeIndex>`. При перестановке строк в подписке
тот же ID мог начать обозначать другой сервер. Для активного узла это создавало
риск незаметной замены конфигурации.

Серверный модуль BROray уже умеет:

- генерировать Xray-конфигурацию из серверного JSON;
- проверять её через `xray run -test`;
- применять активный сервер с резервной копией и откатом;
- запрещать обычное удаление активного сервера.

## Идентичность

Стабильный `importKey` вычисляется серверным модулем из:

- протокола;
- адреса и порта;
- транспорта;
- режима защиты;
- SNI/serverName;
- пути transport/XHTTP/WS/HTTPUpgrade;
- XHTTP mode;
- gRPC serviceName.

Отображаемое имя, URI с секретами и учётные данные не входят в identity.
Поэтому переименование и ротация UUID/password обновляют тот же сервер.
Изменение host, port, transport path/type или TLS/REALITY serverName считается
новым сервером.

## Активный узел

- Если новый набор содержит тот же `importKey`, новая конфигурация активного
  узла сначала генерируется и проверяется Xray.
- После успешной проверки серверный модуль применяет её штатным методом с
  резервной копией и откатом.
- Если конфигурация не изменилась, но старый индексный ID мигрирует на
  стабильный ID, обновляется только указатель активного сервера без перезапуска.
- Если активный `importKey` исчез, вся синхронизация отменяется с
  `ACTIVE_SERVER_CONFLICT`; прежняя рабочая конфигурация остаётся.
- Если новая конфигурация не проходит проверку или применение, синхронизация
  откатывается и сохраняется прежняя рабочая версия.
- Выключение и удаление подписки с активным сервером блокируется до ручного
  отключения или выбора другого сервера.

## Инвариант

Неудачное, пустое, повреждённое или невалидное обновление подписки не удаляет и
не заменяет последнюю рабочую конфигурацию активного сервера.

## Characterization tests

`/opt/broray/tests/subscriptions-selftest.sh` проверяет стабильность identity при
изменении имени и credentials, а также изменение identity при смене host и
transport. Интеграционные ветки активного узла проверяются внутри транзакции
`broray_server_subscription_sync`: предварительная Xray-валидация, блокировка
исчезновения и rollback при ошибке применения.
